# Agent Mention、图片工具记录与设置页交互收口

## 分类与状态

- 分类：功能优化 / 用户体验优化
- 状态：已完成（真实图片识别与 Git 私有远端检查待实机）

## 背景与目标

工作区已有文件、目录和 Skill Mention，以及对话图片识别、图片写入笔记和 Skill Git 更新能力，但部分交互的反馈与真实行为不一致。本需求让文章预览能直接跳到富文本编辑器，Skill 以说明 Tooltip 呈现，文件树可拖入 Agent 输入框生成结构化 Mention，图片识别在工具链中明确呈现已查看的图片；同时统一设置页分段 Tab 的尺寸，并只在 Git 来源确有新版本时展示 Skill 更新入口。

## 范围与非目标

- 范围：文件与目录 Mention 预览及内容预取、输入与消息气泡的 Mention 悬停反馈、文件树到 Agent 输入框的拖放、图片识别执行记录、Agent 工具链实时反馈、设置页自实现 Tab、Skill Git 更新状态。
- 非目标：不改变 Agent 图片识别模型协议、图片对象存储写入策略、Skill 安装来源和权限边界；不恢复已关闭的最终资料/文件回执卡。

## 影响分析

| 维度 | 已确认内容 |
|---|---|
| 写入入口 | 文件树拖放只写入浏览器端 Agent 草稿的结构化 Mention；图片工具记录由后台 Worker 的持久化 run event 写入；Skill 更新检查只读取 Git 远端状态，不修改 Skill 内容。 |
| 读取方与状态传播 | Agent 输入框、用户消息气泡和预览弹窗共用 Mention 元数据；文件 Mention 在悬停时预取正文、弹窗复用内存缓存；刷新后草稿仍由 IndexedDB 还原；会话恢复从 run events 重建图片查看记录；设置 Skill 列表读取 `can_update`。 |
| 边界 | 文件拖放仅接受工作区文件与目录、禁止浏览器文件上传语义；受控图片 URL 必须携带会话归属；远端 Git 检查失败时保守隐藏更新按钮且不影响启停与扫描。Web、Electron 共用前端与 API。 |
| 已检查但不受影响 | 图片写入笔记仍复用既有预览、确认和对象存储链路；MCP、检索和最终资料回执开关不变。 |

## 行为验收矩阵

| 场景 | 前置条件 | 操作 | 预期结果 | 验证状态 |
|---|---|---|---|---|
| 文件预览打开编辑器 | 输入或消息内已有 Markdown 文件 Mention | 打开预览后点击标题链接 | 弹窗关闭，富文本编辑器打开对应文章 | 待验证 |
| Mention 预览平滑打开 | 输入或消息内已有 Markdown 文件 Mention | 悬停后点击 Mention | 正文预取完成后直接显示；未命中缓存也保持固定预览容器，不出现空白重排 | 待验证 |
| Skill Mention 说明 | 输入或消息内已有 Skill Mention | 悬停或键盘聚焦 | 显示单行 Skill 描述，不弹出详情窗口 | 待验证 |
| 文件树拖放 Mention | 文件树有文件或目录 | 拖到 Agent 输入框 | 光标位置插入结构化 Mention，刷新草稿仍可恢复 | 待验证 |
| 图片查看记录 | 本轮提交一张或多张图片 | 等待图片识别 | 工具链显示“查看图片”及受控缩略图，刷新会话后仍存在 | 待验证 |
| 工具链实时反馈 | 发送 Agent 任务 | 服务端受理后等待、执行工具、任务结束 | 立刻显示已等待/处理中计时；真实工具事件逐条入场；结束后默认折叠，等待用户操作时保持展开 | 待验证 |
| 设置 Tab | 搜索、图床、MCP 等设置页可见 | 切换各分段 Tab | Tab 容器与按钮统一高度，窄宽可横向滚动 | 待验证 |
| Skill 更新 | Git 安装的受管 Skill | 打开设置、点击更新后重新读取 | 只有远端存在新提交时显示更新；已同步或更新成功后隐藏 | 待验证 |
