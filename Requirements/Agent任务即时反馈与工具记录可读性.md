# Agent 任务即时反馈与工具记录可读性

## 需求范围

本记录覆盖文件工作区 Agent 的提交反馈、改写截断后的前端状态清理、可恢复任务的模型选择与事件恢复，以及工具行文字可读性，也覆盖历史会话恢复提示、历史搜索摘要和工具详情的阅读层级。它不改变 Worker 的 FIFO、checkpoint、工具权限、确认方式或资料回执开关。

## 影响分析

| 范围 | 处理与结论 |
| --- | --- |
| 写入入口 | 普通发送和改写重发都由 `/api/agent/loop/start` 创建或唤醒 session；恢复任务额外写入原 `agent_task_queue.llm_config_id`。 |
| 读取方与恢复 | `useAgentLoopController` 管理实时消息和 SSE；`FileAgentWorkspace` 管理历史消息、session 时间线、交互和改写后的清理。恢复任务只从返回的事件游标之后订阅。 |
| 失败与取消 | 提交前的本地气泡在建会失败时撤回；改写 API 返回实际取消的 session ID，前端仅取消这些本地订阅和映射。超时、额度、错误 Key 与换模型续跑保留现有 checkpoint 和等待状态。 |
| 平台与安全 | 仅改变浏览器界面与已有 API 的受控字段；不增加密钥、原始 Prompt 或工具结果暴露，不改变 Web、Electron、懒猫的能力边界。 |
| 已检查且不受影响 | Agent 工具权限、确认卡、预览应用、MCP 自动开关、文件读写、资料与文件回执开关均未改动。 |
| 历史恢复与搜索 | 历史列表仍由既有对话 API 返回和筛选；文件工作区只在已保存会话 ID 的首次详情读取期间显示稳定的恢复提示。搜索结果继续由服务端按全文匹配，前端只把最后消息预览压缩为单段短摘要。 |
| 工具详情 | 不改变已持久化的工具事件、脱敏规则或传输字段；仅在展开面板中将 JSON 参数和结果格式化、分区显示，并限制单个代码区的可视高度。 |

## 行为验收矩阵

| 用户入口 | 预期行为 | 验证结果 |
| --- | --- | --- |
| 普通发送 | 发送后即时显示用户消息与“任务已提交，正在准备执行”；服务端确认后不重复添加气泡。 | Browser 真实模型安全回复通过。 |
| 改写早先消息 | 删除其后消息；只清除后续已取消 session 的工具链、交互和草稿；锚点前工具记录保留。 | Browser 发送两轮后改写首轮通过。 |
| 等待态继续 | 当次所选模型写入原队列任务；只消费新事件，旧 final 不重复渲染。 | 自动化通过；真实 Provider 故障与换模型待实机回归。 |
| 工具记录 | 工具名称完整显示，长结果只截断结果部分；继续按钮位于最右侧。 | Browser 核对检索、读文件、新建笔记记录；样式测试通过。 |
| 刷新恢复 | 既有持久化工具记录可恢复，不被改写后的局部清理误删。 | Browser 刷新并重开历史会话通过。 |
| 刷新并恢复上次会话 | 在读取历史列表和详情期间，消息区显示“正在恢复上次对话…”，不会误显示空白对话或空状态；恢复完成后替换为真实消息。 | 待本轮 Browser 回归。 |
| 历史全文搜索 | 命中长 AI 回复时，列表项仅显示归一化后的短摘要，标题、状态、选择、导出和删除操作保持可用。 | 待本轮 Browser 回归。 |
| 工具详情展开 | 已展开工具将调用参数与调用结果分区显示；JSON 使用缩进格式，超长内容只在代码区内滚动，不带动消息页横向滚动。 | 待本轮 Browser 回归。 |

## 测试记录与后续观察

- 已执行 Browser：普通发送、即时提交状态、历史会话切换、既有工具详情展开、模型菜单、改写截断与刷新恢复。
- 已执行自动化和静态检查：Agent 恢复模型与游标、队列唤醒、改写上下文、聊天操作、工作台控件、语法与 diff 检查。
- 待实机回归：需要独立 Provider 测试配置制造超时、额度、错误 Key 和切换模型的恢复场景；当前用户配置未做破坏性修改。
- 本轮已完成：恢复期间显示“正在恢复上次对话…”，搜索结果将连续空白归一并限制为 120 字摘要；工具详情使用“调用参数 / 调用结果”分区，JSON 缩进格式化且代码区独立滚动。
- Browser 已验证新页面无 hydration 错误、历史搜索短摘要、工具详情分区与 JSON 缩进，以及 375px 宽度下消息区和工具详情不横向溢出。
