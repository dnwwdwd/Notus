# Agent 工具链对话内执行记录

## 类型与目标

- 分类：用户体验优化
- 日期：2026-08-02
- 状态：已完成
- 目标：将文件工作区 AI 面板中的 Agent 工具链收敛为附着在本轮回复中的执行记录，降低任务卡对对话阅读的干扰，同时保留真实工具调用、失败说明、停止和继续任务能力。

## 界面与交互规则

1. 仅展示服务端已确认的工具调用、任务暂停或需要用户处理的异常；不展示“执行第 N 轮”“后台任务状态”“创建任务”等内部阶段。
2. 工具记录位于相关用户消息之后：有最终回复时置于该回复正文前；执行尚未形成回复时直接位于本轮用户消息之后。
3. 记录采用单列文字行：顶部显示可折叠的处理概览，行内显示工具语义图标、动作名与简短结果；参数、输出和恢复按钮仅在用户展开后显示。
4. 不使用加载转圈、完成对勾、Agent 头像、Agent 名称标题或独立卡片容器。运行状态只以文字和处理时长表达；失败与停止保留语义图标和操作入口。
5. 不复制 Codex 的品牌、素材或图标；继续使用 Notus 的颜色令牌、图标系统、排版与无障碍语义。
6. 窄宽度下结果摘要可隐藏，动作名和展开入口必须保持可用，长参数与输出可以换行且不能撑破面板。

## 影响分析

- 消息呈现：一条对话可包含多个 Agent session；每个 session 的工具记录必须按 `assistant.meta.session_id` 附着到对应助手回复。尚未产生助手回复的等待任务按任务队列保存的 `user_message_id` 附着到原始用户消息。
- 会话恢复：刷新和切换历史对话时，读取全部带持久化事件的 session，而非仅恢复最近一条。已完成 session 只读取正式回复和工具记录，未完成 session 额外保留草稿与继续入口。
- 运行中的新任务：同一对话可以继续发送任务，后发 session 按服务端 FIFO 排队；每个 session 保持独立 SSE 订阅和时间线，先发任务在后发任务入队后仍持续更新、完成并显示在自身消息旁。旧会话的恢复数据不能覆盖当前 session 的实时步骤。
- 操作归属与隐私：继续、停止等执行记录操作必须携带所属 session ID，不能作用到当前另一个任务；早期 `run_logs` 只显示经过隐私保护的工具名称和完成状态，不展示原始参数、结果或思考草稿。任务达到终态后释放其 SSE 订阅，等待用户确认或回答的 session 保持订阅。
- 等待状态：修改预览、提问卡片及可恢复错误不属于“已处理”，记录头部统一显示“需要处理”，不使用加载转圈或完成对勾。
- 界面适配：工具记录与消息内容同宽，456px AI 面板下摘要可收缩、详情可换行，页面及面板都不能产生横向溢出。

## 验收

- 已用真实 Provider 完成只读 `analyze_folder → read_file` 调用；工具记录附在正式回复前，参数和结果可按需展开。
- 已确认完成工具行无完成对勾，执行中的工具行无转圈；界面不显示 Agent 头像、Agent 名称标题或独立任务卡。
- 刷新页面后，同一对话能恢复已完成任务的工具记录和正式回复；切换到另一条完成的历史对话后，也能恢复其真实工具记录。
- Browser 在固定 456px AI 面板中确认记录宽度未溢出，动作名、展开入口、结果与输入区保持可用。
- `agent-workspace-controls.test.js`、`agent-workspace-chat-actions.test.js`、`workspace-continuity.test.js`、`ui-bug-regressions.test.js`、Web lint 与生产构建均通过。
