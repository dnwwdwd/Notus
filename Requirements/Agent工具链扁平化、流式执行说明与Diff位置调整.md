# Agent 工具链扁平化、流式执行说明、Diff 位置与窄屏确认方式调整

## 分类与状态

- 分类：功能优化 / 用户体验优化。
- 状态：已完成（自动化与本地 Web 页面验证；真实 Provider、Electron、懒猫待实机回归）。
- 对应台账：`REQ-20260810-001`。

## 背景与目标

当前工具链将服务端“执行段”直接显示为“第 N 个执行段”，使用户在多 sub task 任务中先看到内部调度分段，而不是实际调用的工具。累计 Diff 在有最终 Agent 消息时被放入工具链与消息正文之间，打断了回复阅读顺序。

本需求将工具链收束为实际工具、模型重试、确认和一项可展开的“正在思考”步骤。“正在思考”只展示模型明确输出、面向用户的短进度文字，并在接收时流式更新；不展示隐藏推理、Prompt、完整工具参数、文件正文、密钥或未经脱敏的 Provider 内容。最终 Agent 消息存在时，任务累计 Diff 固定显示在该消息气泡及其操作区之后。常规宽度下确认方式显示短标签“自动 / 手动”；最小 AI 面板宽度下，首行保留附件与联网/MCP 图标，确认方式以紧凑 icon Tab 独占下一行；回底按钮位于输入停靠区右上方，不覆盖工具链文字。

## 范围与非目标

- 工具链不再显示“第 N 个执行段”或内部执行段状态；同一任务仍按真实到达顺序显示其调用的工具、重试和确认。
- 支持 OpenAI 兼容与 Anthropic 协议下，模型可见文本的流式读取、脱敏持久化、SSE 推送和历史恢复。
- 切换/新建对话、刷新或重新打开旧对话后，可见“正在思考”内容从持久化 session timeline 恢复，不能依赖当前页面内存。
- 任务累计 Diff 在最终 Agent 消息存在时位于消息气泡下方；尚未形成最终消息时，保留在对应用户消息后的执行记录下方。
- 确认方式 Tab 在 680px 以下收缩为 icon；当容器宽度不超过 390px 时，附件与联网/MCP 保持首行，确认方式仍保持 icon 并独占下一行，模型与发送动作与其底线对齐，所有控件保持可点击且不产生横向溢出。
- 不展示或推断模型隐藏 chain-of-thought，不改变执行段、请求窗口、重试额度、任务变更集、文件写入、确认或回滚语义。
- Word 等附件的解析与单文件全文写入策略本轮仅做现状核查和沟通，不改变长度预算或自动拆分策略。

## 影响分析

| 维度 | 已确认内容 |
|---|---|
| 写入入口 | `completeToolChat()` 在模型可见文本到达时回调；`runAgentLoop()` 将脱敏片段写入 `agent_run_events` 后再 SSE 广播。 |
| 读取方与状态传播 | `useAgentLoopController`、会话详情恢复、SSE 订阅、`MessageList`、`ToolChain` 与 `TaskChangeSetCard` 共同读取同一 session timeline 和任务变更集摘要。 |

| 平台 | Web、Electron、懒猫共享同一 Agent Loop 与持久化事件协议；本轮只改共用前端与服务端，不增加浏览器权限或平台判断。 |

| 已检查但不受影响 | 执行段/请求窗口数据模型、任务变更集聚合、自动/手动确认、知识库聊天、非 Agent 画布、附件解析上限和 Agent 回执卡开关不改变。 |
