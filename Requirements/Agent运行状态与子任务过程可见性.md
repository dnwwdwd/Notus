# Agent 运行状态与子任务过程可见性

## 分类与状态

- 分类：功能优化 / 用户体验优化。
- 状态：已完成（本地 Web 验证；真实 Provider、Electron、懒猫待实机回归）。
- 对应台账：`REQ-20260809-002`。

## 背景与目标

当前 Agent 已持久化执行段、模型请求窗口、工具调用和任务变更集。服务端开始执行段时会发出 `loop_start`，但前端只把工具开始、工具完成、模型重试和等待确认转换为执行记录；模型正在等待响应时，用户只能看到“正在处理 + 计时”。

同一任务涉及多个文件时，工具链只按工具平铺显示，不能看出某次模型决策对应哪些文件操作。用户无法判断任务是在等待模型、正在重试、执行工具、应用文件改动，还是确实已失去响应。

本需求的目标是让正在运行的任务始终展示一个真实、可恢复的当前状态：执行段顺序、当前阶段、已完成工具、目标文件或目录、变更批次和下一步可采取的操作。不得伪造模型尚未输出的计划或文件名。

## 范围与非目标

### 范围

- 在执行记录中显示服务端已持久化的执行段起始、模型请求中、重试、工具执行、工具结果、自动应用、手动确认、完成、失败、取消和恢复状态。
- 将工具调用和产生的变更批次归入触发它的执行段；文件类工具展示受控的目标路径或数量。
- 任务运行中自动展开当前执行段；完成后可折叠，但用户展开后能看到完整分段记录。
- 同一任务仍只展示一张累计 Diff；Diff 详情中可看到每个文件或目录变更来自的执行段和批次摘要。
- 在服务端持久化主模型请求开始后，明确说明“正在等待模型响应”；达到请求超时、重试或不可恢复错误时，展示真实状态和已有累计 Diff。

### 非目标

- 不要求模型事先生成高层任务清单，不把模型未声明的计划当作事实显示。
- 不改变现有执行段的重试额度、主 LLM 超时、工具超时、确认模式、文件写入顺序或任务级累计 Diff 的数据模型。
- 不在工具链中暴露 Prompt、完整工具参数、密钥、文件正文或未经脱敏的模型报错。

## 影响分析

| 维度 | 已确认内容 |
|---|---|
| 写入入口 | `runAgentLoop()` 创建执行段和请求窗口，写入 `agent_execution_segments`、`agent_llm_request_windows` 与 `agent_run_events`；预览工具生成的 operation set 写入任务变更集。 |
| 读取方与状态传播 | session 事件 SSE、历史会话详情、`useAgentLoopController`、`FileAgentWorkspace` 的实时/恢复时间线、`AgentWorkspace` 的 `ToolChain` 和累计 Diff 详情。刷新、断线恢复和继续任务必须使用同一持久化事件重建界面。 |
| 失败、取消与安全边界 | 模型响应前不推测目标文件；重试、超时、可恢复失败、取消和恢复必须有可区分的显示。状态只使用既有脱敏事件字段，不能把模型请求体、密钥或文件全文传到浏览器。 |
| 平台边界 | Web、Electron、懒猫共享服务端 session 和 SSE 语义；布局调整需保持文件树、编辑器和 AI 面板既有响应式规则。 |
| 已检查但不受影响 | 任务级累计 Diff 的聚合、自动/手动逐批写入、知识库聊天、非 Agent 画布对话、Skill/MCP 配置和资料/文件回执开关不因本需求改变。 |

## 行为验收矩阵

| 场景 | 前置条件 | 操作 | 预期结果 | 验证状态 |
|---|---|---|---|---|
| 模型响应等待 | 已创建执行段，模型尚未返回工具调用 | 发送简单文件任务 | 工具链立即显示“第 N 个执行段：正在等待模型响应”和计时，不再只有笼统 running。 | 本地 Browser 通过 |
| 多文件连续修改 | Agent 在多个执行段读取、修改或新建多个文件 | 等待任务完成 | 每个执行段分组显示实际工具和受控路径；累计 Diff 仍只有一张，包含全部净变更。 | 本地 Browser 通过（2 个文件、3 个执行段） |
| 同一段多工具 | 单次模型响应包含多个只读工具调用 | 等待工具完成 | 工具显示在同一执行段下，避免错误拆成多次模型决策。 | 自动化回归通过 |
| 重试 | 某执行段的模型请求遇到 429、超时或可恢复 5xx | 观察自动重试 | 当前执行段显示 `1/5` 至 `5/5`，其他执行段不受影响，并明确处于重试等待。 | 本地 Browser 通过（模拟 429，显示 1/5） |
| 自动应用变更 | 自动确认模式生成文件变更批次 | 等待写入完成 | 执行段显示已应用的文件/目录数量和状态；累计 Diff 立即可打开。 | 本地 Browser 通过 |
| 手动确认变更 | 手动确认模式生成文件变更批次 | 打开累计 Diff 并确认或废弃 | 记录显示等待确认；操作后从原执行段后续跑，状态连续且不重复生成已完成工具。 | 本地 Browser 通过 |
| 刷新或恢复 | 任务在等待模型、重试、工具执行或确认状态 | 刷新页面或重开会话 | 已完成步骤和当前阶段从持久化事件恢复；不能回退为无解释的 running。 | 本地 Browser 通过；断开的订阅会读取持久化事件恢复 |
| 失败或取消 | 已产生至少一个文件变更批次后模型失败或用户停止 | 查看任务 | 错误或取消状态明确，累计 Diff 保持可查看；不暗示后台仍在继续修改。 | 自动化回归通过；真实 Provider 待实机回归 |

## 实现与验证

- 实现：`agentLoop` 在每个执行段开始主 LLM 请求时持久化 `model_requesting`；工具开始、工具完成和变更批次带稳定执行段 ID、段序号和工具序号。前端按执行段分组，并以真实持久化状态显示等待模型、段内重试、工具、自动应用、手动确认和终态；完成的最后一段显示“本执行段已完成”，不保留“正在等待模型响应”。
- 累计 Diff：按需读取的详情保留 `source_batches`，文件头显示“来源：执行段 N · 批次 N”，不会因界面组装操作项而丢失来源字段。
- 恢复：会话详情返回已脱敏持久化运行事件。SSE 订阅异常时，前端先以会话详情恢复当前状态与步骤；手动确认后若原订阅已断开，应用操作会重新订阅原 session 的后续事件。
- 本地 Browser 验证：`http://127.0.0.1:3012/files` 使用仅监听 `127.0.0.1` 的临时 Anthropic 模拟服务。自动模式连续新建 2 个文件，显示 3 个执行段、1 张累计 Diff 和两条来源；手动模式模拟 429 后显示第 1 段 `1/5`，刷新恢复待确认 Diff，点击“全部应用”后继续到第 2 段并收到最终回复。临时配置未调用或改动原有 Provider 与 API Key；测试文件仅写入本地测试数据库。
- 已知待实机回归：真实 Provider、Electron 与懒猫环境，以及真实超时和取消路径。
