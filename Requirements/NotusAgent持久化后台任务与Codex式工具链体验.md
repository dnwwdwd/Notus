# Notus Agent 持久化后台任务与 Codex 式工具链体验

## 需求范围

将 Agent 执行从浏览器 SSE 请求中拆离。切换对话、关闭页签和 Electron 关闭窗口均只解除订阅；后台任务继续执行。显式退出时保存未完成状态，下次启动恢复。界面沿用 Notus 暖色 token，以紧凑、可折叠的工具时间线呈现过程，不使用 Codex 品牌资产。

## 影响分析

| 范围 | 写入入口 | 读取与恢复 | 失败、取消与安全边界 |
| --- | --- | --- | --- |
| Agent 队列 | `/api/agent/loop/start` 创建用户消息、session 和 `agent_task_queue` | Worker 领取任务；会话详情和 SSE 按事件 ID 回补 | 只有取消接口写入 `cancelled`；不保存 API Key，仅保存配置 ID 与受控输入引用 |
| 运行事件 | Worker/Loop 先落 `agent_run_events` 再广播 | `/api/agent/sessions/:id/events?after=` 回补后订阅 | 断订阅不影响任务；应用重启把 `running` 重新排队 |
| 提问卡 | interaction 回答与 answer message 已事务化保存 | 对话读取返回 pending、answered、failed、stale 卡片和时间线 | 回答幂等，回答后仅唤醒原任务，仍受同会话 FIFO 约束 |
| 桌面端 | Electron 主进程管理窗口、托盘与通知 | 关闭窗口后服务保活；显式退出下次启动 Worker 接管 | 完全退出期间不执行模型调用；系统托盘行为需 macOS/Windows 实机回归 |
| 不受影响 | 知识库 `/api/chat`、画布非 Agent 对话、AGENT_TASK_RECEIPTS_ENABLED | 无 | 保持既有协议和临时关闭开关 |

## 行为验收矩阵

| 用户入口 | 应验证行为 |
| --- | --- |
| 发送首条/后续 Agent 消息 | 立即返回 202 和队列位置；同会话严格 FIFO，跨会话可并行领取 |
| 切换或重开对话 | 旧订阅关闭但任务不取消；重开后按持久化事件恢复相同工具顺序 |
| 关闭窗口/显式退出 | 关闭隐藏到托盘；显式退出后未完成任务下次启动恢复 |
| LLM 临时或配置错误 | 最多三次自动重试后等待；输入仍可发送；“继续任务”可唤醒 |
| 提问卡回答 | 回答后自动续跑；重启与重开会话后仍可显示问题、答案和时间 |
| 取消 | 显式停止成为 `cancelled`，后续重启不得复活 |
| UI | 工具节点可键盘展开；长参数折叠；窄窗单列；暗色 token 与 reduced motion 不回归 |

## 2026-08-01 界面打磨补充

- 工具链没有真实事件时保持空白，不以“准备上下文”等推测步骤冒充执行进度。
- 时间线使用紧凑的分隔线行：状态图标、动作名、单行摘要与按需展开的参数/结果；停止操作属于任务时间线，不占用模型选择区。
- 本条旧界面规则已由 `REQ-20260802-002` 替代：工具记录附着在对应消息中，不显示 N 头像、“Notus Agent”名称或独立任务卡。没有活动时不创建空白容器；`queued_resume`、模型重试和模型配置恢复记录仍默认展开，并提供“继续任务”或“配置完成后继续”。
- AI 独占工作区限制消息与输入列宽，避免在大屏铺满；窄面板使用单列工具栏与横向可滚动的次要控制，模型选择不会挤压发送操作。
- 验收增加：首屏不显示伪步骤、模型右侧无孤立状态点、456px 面板与窄窗口不溢出。
