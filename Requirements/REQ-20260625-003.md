# REQ-20260625-003：恢复创作页 @b 块级 Agent 工具并优化图片与导出链路

## 分类

功能优化

## 需求描述

创作页需要继续支持通过 `@b1`、`@b2`、`@b3` 等块引用进行文本块级修改，并将该能力纳入 Agent Loop 工具调用，减少任务循环次数并提升修改精度。

编辑器本地图片不再以内嵌 base64 写入 Markdown，而是保存到与笔记目录同级的图片资源目录，并在 Markdown 中使用相对路径引用。导出 Markdown 时需要同时导出笔记目录和图片资源目录，避免单个 Markdown 文件过大导致 VS Code、Typora 等常见工具无法打开。

导出文件列表需要把当前已选文件置顶，避免用户误以为没有选中。

## 落地说明

- Agent Loop 新增 `preview_canvas_blocks` 工具，用于根据 `@b1`、`@b2` 等引用生成创作页块级修改预览。
- 创作页发送 Agent 任务前会保存当前未保存块内容，并把当前块快照附加到任务上下文中，便于模型直接调用块级工具。
- 编辑器粘贴图片和工具栏插入本地图片统一上传到 `assets/images/`，Markdown 保存相对路径，编辑器渲染时通过本地图片预览 API 显示。
- Web 默认资源目录从 `notes/.assets` 调整为与 `notes` 同级的 `assets`。
- 文件导出接口统一返回 zip，选中的 Markdown 位于 `notes/` 下，资源目录按实际位置导出为同级 `assets/` 或 `notes` 内对应目录。
- 导出弹窗中已选文件在当前搜索结果内置顶显示。
