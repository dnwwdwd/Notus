# REQ-20260716-004：将 Agent 对话图片插入笔记并复用图片存储设置

## 分类

功能需求。

## 交付

### 意图与目标处理

- 用户在同一轮上传图片并提出“整理到某笔记”“插入到某文件”等写入请求时，Agent 识别写入意图和图片来源。
- 当前输入、`@` Mention 或最近对话能唯一确定目标 Markdown 路径时，Agent 直接生成图片变更预览。
- 目标笔记无法唯一确定时，Agent 调用 `ask_question_card`。卡片列出检索到的候选笔记，并提供“新建笔记”选项；用户回答后在同一 session 中继续生成预览。
- 当前轮图片在输入上下文中带会话受控引用。后续任务需要历史图片时，Agent 先用 `list_conversation_images` 获取清单，再用 `read_conversation_images` 选择图片；只把选中的视觉 block 重注入该轮上下文。
- 未唯一确定目标时，卡片最多给出 3 个候选，并提供“手填已有路径”和“新建笔记”。后两项选中后才显示 Markdown 路径输入题；候选项保存真实相对路径作为回答值。
- 卡片单选后自动进入下一题；所有可见题完成后，在同一个 `ClarifyDrawer` 中展示全部问题和回答，用户可点任一项返回修改，再直接提交续跑。

### 图片存储与写入

- 服务端使用 `notus-conversation-image://<message-id>/<image-id>` 受控引用，按所属会话、消息和图片 ID 校验来源；不接受客户端提供临时文件路径，也拒绝跨会话引用。
- 图片写入继续使用编辑器的图片存储策略：本地模式保存到资源目录并返回相对 Markdown 路径；对象存储模式写入 COS、OSS、R2 并返回公开 URL。
- 图片存储逻辑已从编辑器上传 API 抽为共享服务，编辑器上传和聊天图片写入共同调用。
- 自动确认和手动确认都走同一条写入路径。图片在“应用预览”时复制进目标存储，随后把最终 Markdown 图片地址写入笔记。
- 会话图片临时文件保存在 `<sessionDir>/images`，通过用户消息元数据与会话逻辑绑定。当前不因会话完成、取消、过期、删除、回滚或笔记应用自动销毁；上传失败的中间文件会清理。

### 图片 diff

- 图片新增、替换、移除归入现有 operation set，和文本变更一起进入 DiffDialog。
- DiffDialog 解析 Markdown 图片变更并直接渲染缩略图：新增显示新图；移除显示原图；替换并排显示旧图和新图。
- 预览阶段使用按会话校验的聊天图片预览接口；应用后，本地图片使用笔记内容图片代理，对象存储图片使用公开 URL。
- “移除图片”表示删除笔记内的图片引用。默认保留资源文件和对象存储文件，避免删掉仍被其他笔记引用的内容。
- 预览被废弃、文件已 stale 或写入失败时，目标笔记不修改，聊天图片仍保留在会话历史中。
