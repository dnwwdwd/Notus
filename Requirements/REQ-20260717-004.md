# REQ-20260717-004 关闭窗口后完整恢复文件工作区

## 基本信息

- 日期：2026-07-17
- 分类：用户体验优化
- 状态：已完成
- 来源：用户提出

## 问题与目标

文件工作区原本会保存当前文件和两个面板的开关状态，但应用启动后又把个性化默认展开值套用到已恢复的文件上。用户关闭编辑器或 AI 面板后重开应用，会看到上次文档配上新的默认 AI 面板组合。

关闭窗口后重新打开应用时，文件工作区需要恢复上次的当前文档、编辑器开关和 AI 面板开关。

## 实现规则

1. `AppContext` 在浏览器工作区状态完成恢复后提供恢复完成标记及启动时保存的当前文件 ID。
2. `/files` 发现当前文件来自启动恢复时，不再套用个性化默认面板值，直接使用 `notus-files-workspace-panels` 的已保存组合。
3. 用户在已运行的工作区中清除文件选中后再打开文件时，仍按个性化默认值决定首次展开组合。

## 验证

1. 关闭编辑器、保留 AI 面板和某篇已打开文档后关闭窗口，重新打开仍显示同一文档和仅 AI 面板。
2. 关闭 AI 面板、保留编辑器后关闭窗口，重新打开仍显示同一文档和仅编辑器。
3. 清除当前文件选中后再打开任一文件，个性化默认面板值继续生效。
4. 已通过 `npm run lint:web` 与 `npm run build:web`。现有 `workspace-layout-and-topbar` 静态测试仍有一条旧 Agent 输入常量断言未随既有实现更新，不作为本条验收结果。
