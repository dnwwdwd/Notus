# REQ-20260723-005：AI 工作台控制收敛、对话检索与窄窗口布局

## 分类与状态

- 分类：功能优化 / 用户体验优化
- 状态：已完成

## 产品目标

高频 AI 工作台的输入控制只暴露用户当下能决定的内容；历史对话要能从对话名称和真实消息中找回；窗口缩小时，AI 对话保持连续可用，文件树和编辑器按优先级让出空间，且不会在窗口回宽时擅自打断用户的布局选择。

## 需求与决策

1. MCP 是任务级自动开关。关闭时按钮不高亮；点击后开启并弹出仅含“自动”的下拉项；再次点击关闭并收起下拉。控件不显示 Server 名、传输类型、说明文案或“关闭”选项。历史的指定 Server 偏好读取后归一为自动。
2. 自动/手动确认仍保留短标签，tooltip 与无障碍名称分别为“自动应用修改”“手动应用修改”。
3. 模型菜单提供“搜索模型或 Provider”输入框，按模型显示名、Provider 名和配置名做不区分大小写的包含匹配；无结果明确提示。
4. 历史抽屉提供“搜索对话或消息”。服务端在当前会话范围内以不区分大小写的模糊匹配搜索对话标题、用户消息和 AI 消息，避免只搜索最后一条预览而漏掉历史内容。
5. 窗口宽度缩小时，960px 以下优先自动收起文件树；双栏仍可显示时 AI 面板固定为 456px，富文本编辑器压缩剩余空间；640px 以下再自动收起编辑器，AI 面板占满工作区。窗口重新变宽时，自动收起的文件树和编辑器保持收起，用户通过对应控制显式展开后才恢复。

## 验收

- MCP 点击行为与联网一致，开启态高亮，发送请求仅携带 `{ mode: 'auto' }` 或 `{ mode: 'off' }`。
- 模型搜索可用 Provider 名与模型名命中；历史搜索可用对话标题、任意用户消息或任意 AI 消息命中。
- 在 390px、640px、960px、1024px、1366px 宽度检查不发生横向溢出；AI 在双栏的窄宽阶段保持 456px，窗口拉宽不自动展开文件树或编辑器。
