# REQ-20260725-002：对外 MCP Server、Token 与受控笔记操作

## 分类与状态

- 分类：功能需求。
- 状态：已完成。

## 已确认的产品口径

1. Notus 以 MCP Server 身份向外部 Agent 提供能力，与当前“Notus 作为 MCP Client 配置外部 Server”的能力分开。
2. 用户可创建多个 MCP Token；每个 Token 创建时固定为“自动应用”或“手动确认”。手动确认沿用 Notus 的变更预览与确认界面，自动应用仍需通过内容与版本冲突校验。
3. 对外 MCP 永不提供删除文件或目录的工具。
4. 不提供联网搜索；提供按文件名/路径匹配的文件搜索。
5. 提供有效 Skill 列表，以及不含密钥、Header、环境变量和工具参数的 MCP Server 列表。
6. 每个 MCP Token 都保存独立的工具权限集合。创建和编辑 Token 时以开关授权可用工具；基础只读工具默认开启，文件写入、移动和重命名默认关闭。`get_change_status` 仅属于手动确认 Token，自动应用 Token 不显示、不可配置且不会注册该工具。Token 的自动/手动确认模式与这些工具开关共同决定外部 Agent 的实际能力。

## 实现结果

- 对外入口为 `POST /api/mcp` 的无状态 Streamable HTTP MCP，使用 `Authorization: Bearer <token>` 鉴权。Token、Server 与待确认变更的设置管理接口迁至 `/api/settings/mcp/*`，不与外供入口共用路径。
- Token 可多条创建、编辑、停用、删除和重新生成；数据库只保存 SHA-256 哈希，明文只在创建或重新生成时返回一次，默认永不过期。
- 基础只读工具默认开启；写入、移动、重命名由 Token 开关逐项授权。状态查询只在手动确认 Token 的权限区出现并按其开关注册；自动 Token 即使存在旧配置也会在服务端剔除该权限。对外不注册删除和联网搜索。
- 写工具均校验 `expected_hash`；局部 patch 还要求 `old` 精确且唯一命中。自动 Token 直接写入，手动 Token 生成独立待确认变更，可在 MCP 设置页查看 Diff、应用或拒绝，并用 `get_change_status` 查询。
- 对外 Skill/MCP 列表只返回允许的摘要；审计记录不保存 Token、Header、请求正文或文件正文。
- MCP 设置页以内容宽度的“调用 MCP”和“MCP 服务”两个标签分隔 Notus 调用外部 Server 与外部 Agent 调用 Notus 的配置，默认打开前者。
- 创建或重新生成 Token 后，一次性明文展示弹窗将复制操作置于 Token 输入框尾部，沿用密码输入框的紧凑 icon 操作形式。
- 懒猫清单仅将 `/api/mcp` 声明为 `public_path`，使携带 MCP Bearer Token 的外部请求不被平台 OAuth 拦截，同时保留设置管理接口的平台访问保护。
