# 会话列表 Agent 任务状态提示

## 类型与目标

- 分类：用户体验优化
- 日期：2026-08-02
- 状态：已完成
- 目标：在文件工作区的历史对话列表中标记仍有非终态 Agent 任务的对话，让用户切换或新建对话后能直接识别哪些任务仍在执行、等待回答或可继续。

## 界面与交互规则

1. 每条对话只显示一个紧凑的状态标记，不新增独立任务卡、加载转圈或控制按钮。
2. 状态由该对话中最需要用户关注的非终态 session 决定：等待回答优先于等待确认、可继续、运行中与排队。
3. 标记文案为“等待回答”“等待确认”“可继续”“正在执行”或“等待执行”；有多条非终态任务时附带数量。
4. 标记使用现有 `clock` 图标、Notus 颜色令牌和与历史列表一致的圆角；图标与文字一起提供可访问名称。点击状态标记不拦截对话选择。
5. 已完成、取消或失败且不可继续的 session 不显示标记。状态标记只提示，不改变停止、继续、回答或队列顺序。

## 影响分析

| 范围 | 写入入口 | 读取方与刷新 | 失败、取消与平台边界 |
| --- | --- | --- | --- |
| `agent_sessions` | 既有 Worker、交互回答、取消与恢复流程写 session 状态；本需求不新增写入 | `listConversations()` 汇总每个对话的非终态 session；`ConversationDrawer` 渲染标记 | 不返回 ticket、任务输入、工具参数或错误正文；取消和终态自然移除标记 |
| 会话列表 API | `GET /api/conversations` 只读增加状态摘要字段 | 工作区初次加载、打开历史抽屉、搜索、任务创建/进入等待/完成后刷新列表 | API 不改变会话详情、SSE、FIFO 或 Electron/懒猫的后台执行行为 |
| 历史抽屉 | 无持久化写入 | 读取状态摘要并显示；抽屉打开期间定时刷新，以反映后台任务变化 | 网络失败保留当前列表，不把失败当成任务状态；窄面板文字可截断但状态仍可读 |
| 已检查且不受影响 | 知识库 `/api/chat`、MCP、Skill、笔记与索引 | 无 | 不新增模型调用、外部 API、密钥或运行时权限 |

## 行为验收矩阵

| 场景 | 预期 |
| --- | --- |
| 对话没有非终态 Agent session | 不显示状态标记 |
| Worker 正在运行 | 显示“正在执行” |
| session 等待提问卡回答 | 显示“等待回答”，优先于同对话排队任务 |
| session 等待预览或额度确认 | 显示“等待确认” |
| `queued_resume`、`waiting_retry`、`waiting_model_recovery` | 显示“可继续” |
| 多条非终态 session | 显示最高优先级状态及数量 |
| 任务完成、取消或成为不可恢复失败 | 下次列表刷新后移除状态标记 |
| 窄宽度、暗色主题与键盘访问 | 不溢出；状态有文字和 `aria-label`；对话选择保持可用 |
