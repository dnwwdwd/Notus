# 创作页Agent提示词明确当前打开文档

## 类型

功能优化

## 背景

创作页右侧 AI 对话记录在前端展示上不应额外绑定或暴露文件名，避免历史消息列表被当前文档标题污染。但 Agent 执行写作、改写和文件级预览时，必须明确知道用户当前打开的是哪篇文档，不能只依赖会话绑定或授权路径推断。

## 需求

1. 创作页对话消息前端展示继续保持通用聊天样式，不在消息头部强制展示当前文件名。
2. 发给 Agent Loop 的任务 goal 必须包含当前打开文档的可见名称。
3. 如果能拿到文件路径，任务 goal 同时包含当前文章路径。
4. 当前文档信息只作为 Agent 执行上下文，不改变历史会话抽屉的展示和选择逻辑。

## 实现结果

1. `notus/pages/canvas.js` 构造 Agent 任务时，优先从当前文章文件、文章对象和 active file 解析可见文档标签。
2. Agent Loop goal 现在包含：
   - `当前打开文档：<可见文档名>`
   - `当前文章路径：<path>`（存在路径时）
3. 现有对话历史列表、消息气泡和前端标题展示未新增文件名绑定。

## 验收

- 创作页打开某篇文档后发送 Agent 任务，后端收到的 goal 明确包含当前打开文档名称。
- 如果当前文档有路径，goal 同时包含该路径。
- 聊天消息列表不额外显示当前文件名。
