# 文件工作区与全局页面响应式适配

## 分类

功能优化 / 用户体验优化

## 背景

当前界面按 `1360 × 800` 的固定桌面工作区尺寸渲染。浏览器窗口缩小后，根节点与 Shell 仍保持 1360px 最小宽度，页面通过横向裁切而不是重排展示，导致编辑器、AI 面板、设置弹窗和初始化流程的内容无法完整使用。

## 目标

在保留现有暖白工作区视觉与桌面高效布局的前提下，让所有当前可见路由和共享界面组件在常见窄窗口中完整可用。

1. 移除全局与 Shell 的固定最小窗口尺寸，页面宽度不再强制为 1360px。
2. 文件工作区在中等窗口缩小侧栏和双栏最小宽度；窄窗口的编辑器与 AI 面板上下排列方案已由 `REQ-20260722-004` 替换为文件树抽屉、编辑器收起和 AI 主工作区，继续禁止整页横向溢出。
3. 小屏幕中的 Sidebar 改为可展开的临时抽屉；设置导航改为水平可滚动栏，设置内容随可用宽度收缩。
4. 统一约束弹窗、文档查找、通知、图片预览、编辑器正文、工具栏与初始化页面，使它们不越出视口；代码块和表格保留各自内部横向滚动能力。
5. 对 `/files`、`/settings/*`、`/setup`、`/indexing`、`/login`、`/404` 及 `/knowledge`、`/canvas` 兼容跳转路径，在 1366、1024、768、390px 宽度下做浏览器回归。

## 实施范围

- `styles/globals.css` 中的全局断点、共享组件边界和移动端样式。
- `Shell`、`Sidebar`、`ResizableLayout`、文件工作区、设置弹窗与初始化页面的必要布局标识和行为。
- 产品、技术、界面和阶段进度文档中的窗口尺寸与响应式口径。

不改变 AI 业务流程、文件读写、设置项、路由定义或现有视觉 token。

## 验收标准

1. 在 1024px 及以下宽度，页面根节点宽度不超过视口，浏览器不出现由应用 Shell 引起的横向滚动。
2. 原 768px 及以下的编辑器与 AI 面板上下排列验收口径已由 `REQ-20260722-004` 替换；当前应收起编辑器并保留 AI 面板为主工作区。
3. 在 390px 宽度，用户可打开侧栏、设置、搜索、通用弹窗和图片预览，内容与关闭入口均在视口内。
4. 宽表格、代码块或 diff 仅在自身内容区滚动，不推动页面横向溢出。
5. 1366px 桌面视口维持现有三栏工作区的视觉层级与拖拽分栏能力。

## 状态

已完成，窄窗口分栏策略已由 `REQ-20260722-004` 更新。

## 验证

- 浏览器实测 `/files`：1366px 保留三栏，1024px 无页面横向溢出，768px 改为编辑器与 AI 上下排列，390px 内容不被侧栏遮挡且侧栏可作为抽屉展开。
- 浏览器实测 390px 下的 `/settings/model`、`/indexing`、`/login`、`/404` 与全局搜索弹窗，根节点宽度均未超过视口；设置导航可横向滚动，弹窗关闭入口在视口内。
- `/knowledge`、`/canvas` 仍按现有规则跳转 `/files`；当前环境中 `/setup` 因已完成初始化自动跳转 `/files`，未修改其业务跳转条件。
- `npm --prefix notus run lint`、`node notus/tests/ui-bug-regressions.test.js`、`npm run build:web`、`git diff --check` 通过。
