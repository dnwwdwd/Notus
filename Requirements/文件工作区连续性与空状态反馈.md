# 文件工作区连续性与空状态反馈

## 分类与状态

- 分类：功能优化 / 用户体验优化。
- 状态：已完成，待 Web / Electron 实机回归。

## 目标与范围

- Agent 正在运行或有待回答的提问卡片时，AI 面板不可收起，并给出简短友善的原因提示。
- 所有“打开文件”入口都恢复富文本编辑器；文件树选择、Diff 路径和全局搜索采用同一规则。
- 设置导航中的 Skill 图标只在当前项选中时使用强调色；AI 输入框无可用 MCP Server 时展示“暂无 MCP 服务”提示。
- 不修改 MCP Server 的可用性判定、任务授权范围、编辑器内容保存规则或 Agent 写入权限。

## 影响分析

| 维度 | 已确认内容 |
|---|---|
| 写入入口 | 文件工作区持久化 `workspacePanels` 由 `pages/files/index.js` 写入；Agent session 与提问交互状态分别由 Loop、interaction API 写入；MCP Server 配置仍只由设置 API 写入。 |
| 读取方与状态传播 | `FileAgentWorkspace` 读取 Loop/待处理 interaction 并将 AI 面板锁定状态传给文件页；`TopBar`、文件树、Diff 和路由选择共享文件页的编辑器展开逻辑；`AgentInput` 根据已启用 MCP Server 数量呈现按钮提示。 |
| 刷新与恢复 | 布局切换保持 AI 工作区处于同一 React 节点，提问卡的未提交回答保存在工作区内存中；页面刷新后仍以服务端 pending interaction 恢复卡片，未提交回答不承诺跨刷新保存。 |
| 失败与取消边界 | 提问提交失败保留当前回答；回答成功后只恢复同一个持有 session token 的 Loop。任务失败、取消或 interaction 不再 pending 后立即解除 AI 面板锁定。 |
| 平台与安全边界 | Web、Electron 共用同一页面逻辑；不新增运行时判断、不在前端持久化 session token、不暴露 MCP 密钥。 |
| 已检查但不受影响 | 文件内容保存、索引、Diff 应用/回滚、MCP 工具缓存与 Skill/MCP 的设置 API 均不改变。 |

## 行为验收矩阵

| 场景 | 前置条件 | 操作 | 预期结果 | 验证状态 |
|---|---|---|---|---|
| 文件树打开 | 编辑器已收起 | 在文件树选择任意 Markdown 文件 | 文件被选中，编辑器立即展开 | 自动回归通过；待实机回归 |
| 提问卡连续性 | Agent 提问卡已回答部分问题 | 收起编辑器、切换文件再返回 | 已选答案仍在；不要求重复回答 | 自动回归通过；待实机回归 |
| 面板保护 | Agent running 或有 pending 提问卡 | 点击或快捷键收起 AI 面板 | 面板保持展开，显示原因提示 | 自动回归通过；待实机回归 |
| 提问续跑 | 已提交有效提问卡回答 | 恢复同一任务 | checkpoint 注入回答；Loop 结束后 session 退出 `waiting_confirm` | 自动回归通过；待真实 LLM 会话回归 |
| Diff 跳转 | 编辑器收起、Diff 中存在 Markdown 文件 | 点击顶部路径或文件列表路径 | 关闭 Diff，打开对应文件并展开编辑器 | 自动回归通过；待实机回归 |
| 设置与 MCP 空态 | Skill 菜单项未选中；无已启用 MCP Server | 查看导航、悬浮 MCP 按钮 | Skill 图标继承普通文字色；MCP tooltip 显示“暂无 MCP 服务” | 自动回归通过；待实机回归 |
