# 文档治理闭环与跨模块验收

## 分类与状态

- 分类：功能优化。
- 状态：已完成。

## 背景与目标

现有流程已经规定需求分类、文档优先级和同步维护，但跨模块改动缺少统一的文档导航、影响分析格式和行为验收门槛。资源状态更新等变更容易只覆盖一个写入入口或一个前端消费者。

本需求保留现有工作流和项目专属约束，补齐短而可执行的交付闭环。治理规则不引入 RFC、ADR、额外项目看板或独立任务系统。

## 范围与非目标

- 新增 `docs/文档地图.md`，按功能域定位必读文档、主要代码、测试和平台限制。
- 在 `AGENTS.md` 与 `CLAUDE.md` 加入跨模块影响分析、行为验收和“待实机回归”的交付门槛。
- 在 `Requirements/需求文档规范.md` 定义简版需求和跨模块需求记录格式。
- 保留既有需求台账、Bug 台账、PDD、PRD、UI Guide 与业务流程文档的职责和优先级。
- 不修改产品功能、运行时代码、数据结构、平台能力或打包链路。

## 影响分析

| 维度 | 已确认内容 |
|---|---|
| 写入入口 | 治理规则由 `AGENTS.md` / `CLAUDE.md` 维护；需求记录由 `Requirements/需求文档规范.md` 和 `Requirements/需求总台账.md` 维护；导航关系由 `docs/文档地图.md` 维护。 |
| 读取方与状态传播 | 后续执行需求的开发者与 Agent 先读文档地图，再按原优先级读取事实文档；跨模块 REQ 在实现前记录影响分析，交付前回填行为验收。 |
| 边界 | Bug 仍只进入 `docs/Bug台账.md`；没有跨模块或持久化状态影响的小改动使用简版记录；实机受限时必须显式保留待回归项。 |
| 已检查但不受影响 | PDD、PRD、UI Guide、PROGRESS 和业务流程文档描述产品行为、技术方案、界面和里程碑。此次只调整研发治理，不改变其事实内容。 |

## 行为验收矩阵

| 场景 | 前置条件 | 操作 | 预期结果 | 验证状态 |
|---|---|---|---|---|
| 跨模块功能优化 | 同一资源有多个写入入口或读取方 | 开始实现前创建/补全 REQ | 记录写入入口、读取方与状态传播、边界和不受影响项 | 已完成 |
| 跨模块 Bug | 现有承诺或实现失效 | 记录并修复 Bug | Bug 台账包含影响范围、相关流程检查和行为验证 | 已完成 |
| 无法实机验证 | 依赖真实 API Key、目标平台或外部资源 | 完成交付 | 条目列出待实机回归，不以静态检查替代 | 已完成 |
| 文档导航 | 开始新的需求 | 查询 `文档地图.md` | 能定位相应必读文档、代码、测试和平台限制 | 已完成 |
| 协作文档一致性 | 修改治理规则 | 比对 `AGENTS.md` 与 `CLAUDE.md` | 两份文件内容完全一致 | 已完成 |
