# 附件文件名截断、上传类型与窄屏图床标签优化

## 分类与状态

- 分类：功能优化 / 用户体验优化。
- 状态：已完成。

## 背景与目标

当前 Agent 输入区的附件 chip 会受到文件名长度影响，长名称在窄面板中不易阅读；文件树虽然使用省略号，但没有在实际截断时提供完整名称。文件选择器与粘贴解析共用同一条业务链，但 CSV 尚未进入前端和服务端支持列表。个性化页的图床 Tab 已有紧凑文案，却没有在缩略状态提供完整名称提示。

本次统一附件的固定尺寸与文件名反馈，令选择器、剪贴板和服务端解析支持同一组文档类型，并让文件树与窄屏图床标签在不增加页面横向溢出的前提下保留完整语义。

## 范围与非目标

- 范围：Agent 输入区解析附件 chip、文件树文件/目录名称、解析附件选择器与剪贴板文件、CSV 文本解析、个性化图片上传位置 Tab。
- 非目标：不改变图片上传接口、附件数量和大小上限、消息数据结构、图床配置保存 API、文件树排序或导航行为。

## 影响分析

| 维度 | 已确认内容 |
|---|---|
| 写入入口 | Agent 输入区文件选择器、剪贴板文件项和长文本转 TXT；附件上传 API 继续写入会话临时附件目录；个性化 Tab 继续调用既有 `/api/settings`。 |
| 读取方与状态传播 | 前端 `AgentWorkspace` 用选择器声明扩展名/MIME，实际以支持的扩展名校验并展示 chip；服务端 `attachmentParsing` 与上传路由沿用同一扩展名列表；历史消息复用 `FileChip`；文件树 `Sidebar` 只读取文件树数据；`SegmentedTabs` 仅改变标签渲染与 Tooltip。 |
| 边界 | CSV 按 UTF-8 纯文本解析；图片仍分流到图片上传链路；不支持的扩展名继续在前端提示并由服务端拒绝；Tooltip 单行且受视口宽度限制；文件树仅在 DOM 确认发生截断时启用 Tooltip。Web、Electron 共享同一前端和解析逻辑。 |
| 已检查但不受影响 | 图片上传 API、对象存储配置和文件树选择/拖放逻辑不改；Agent 队列、SSE、会话恢复和草稿持久化不改；富文本编辑器内容和 Markdown 导入仍只接受 `.md`。 |

| 场景 | 前置条件 | 操作 | 预期结果 | 验证状态 |
|---|---|---|---|---|
| 长文件名附件 | Agent 输入区可上传解析附件 | 选择名称较长的 PDF/MD/CSV | chip 宽度固定在内容列内，名称单行省略；悬浮 Tooltip 展示完整文件名且不换行 | 已验证：Browser 实测 240px chip 与单行 Tooltip |
