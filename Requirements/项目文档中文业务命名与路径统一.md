# 项目文档中文业务命名与路径统一

## 分类与状态

- 分类：功能优化。
- 状态：已完成。

## 背景与目标

项目文档过去混用英文缩写、实现规格名和 `REQ-日期-序号` 文件名。需求记录的稳定编号适合台账追踪，不适合作为用户浏览和业务协作时的文档名称。本次统一使用中文业务名称，并保持协作入口和文档导航可用。

## 范围与非目标

- `docs/` 下的产品、技术、业务流程、治理和验证文档改为中文业务名称。
- `Requirements/` 下的需求明细改为台账标题对应的业务名称，`需求总台账.md` 保留稳定记录编号与状态字段。
- 同步 `AGENTS.md`、`CLAUDE.md`、`README.md`、文档地图、需求记录和历史文档中的路径引用。
- `AGENTS.md`、`CLAUDE.md`、根目录 `README.md` 保留为工具约定入口名称；不改动代码、接口和运行时行为。

## 影响分析

| 维度 | 已确认内容 |
|---|---|
| 写入入口 | 文档文件重命名、文档内链接和治理规则引用更新。 |
| 读取方与状态传播 | Agent 实施前阅读规则、文档地图、README 导航和需求台账均切换到新路径；产品代码不读取这些 Markdown 文件。 |
| 失败、取消与恢复 | 本次没有运行态或持久化业务状态变化；旧路径引用通过静态扫描清理，缺失链接通过相对 Markdown 链接检查验证。 |
| 平台与安全边界 | Web、Electron、懒猫代码与权限边界不变；不新增凭据、接口或构建产物。 |
| 已检查但不受影响 | `notus/`、`desktop/`、构建脚本和 LPK 产物不改动；根目录约定入口名称保持不变。 |
