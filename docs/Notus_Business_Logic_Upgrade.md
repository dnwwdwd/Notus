# Notus 业务逻辑说明

> 更新时间：2026-07-22

## 1. 统一工作区状态

全局状态继续维护文件树、当前文件、Sidebar 折叠、文件树展开、TOC、滚动位置和待定位引用。产品页面状态收口到 `files`。

文件工作区额外维护：

- `editorOpen`：富文本编辑器是否展开。
- `agentOpen`：AI Agent 面板是否展开。
- `workspaceLayout`：保存编辑器与 AI 面板的双栏宽度百分比。

工作区的响应式重排不改变这些持久化字段或 Agent 调度：宽屏按原百分比显示可拖动双栏；窄于 960px 时 Sidebar 改为临时抽屉；窄于 760px 且 `workspacePanels.editorOpen / agentOpen` 同时为真时，由这两个持久化字段与视口状态共同派生当前编辑器和分隔线平滑收起、AI 面板同步占满工作区。恢复的开关和宽度记录继续生效，页面不再通过固定 1360px 画布横向裁切，也不把双栏改为上下区域。

前两项与宽度持久化在浏览器。打开首个文件时读取个性化默认值；已打开文件之间切换不改变当前值。双栏宽度以编辑器和 AI 面板两个百分比一起保存，初始化时恢复。再次点击当前文件会清除 `activeFileId`，编辑器回到空态但不改变 AI 面板状态。

`TopBar` 的富文本编辑器和 AI 面板控制分别响应 `Mod+B`、`Mod+U`，由快捷键设置统一管理；`Mod+U` 命中时阻止浏览器默认动作。Tooltip 只说明操作，不显示快捷键组合。搜索入口提示为“搜索文件”。

## 2. 文件与 Agent 的关系

- 当前文件是编辑器和 TOC 的上下文，不是 Agent 的隐式上下文。
- AI 面板可以没有当前文件；此时可执行普通对话、工作区检索、文件创建和目录任务。
- 发送 Agent 任务前，当前编辑器的未保存内容先落盘，避免 Agent 基于旧版文件生成修改。
- Agent 写入后刷新文件树，清除当前文件缓存并重新载入编辑器。
- 文件树取消当前文档时同步清理待定位引用，并移除 URL 中的 `fileId`，避免路由同步逻辑立即重新选回该文件。

## 3.1 富文本表格

工具栏的“插入表格”弹窗接收行数和列数，创建带表头的 Tiptap table 节点。节点由 `tiptap-markdown` 序列化为 Markdown 表格，后续可继续编辑、复制和保存。

AI 输入区默认保持 5 行文字高度。输入框和消息列复用父容器 95% 的宽度约束，在 AI 独占和双栏布局中都随面板宽度变化；用户消息气泡保持右对齐与内容宽度上限。已发送图片与解析附件一样在文字气泡上方独立成行，图片行只显示缩略图，不带气泡背景。消息滚动区为输入区留出底部空间，避免覆盖 AI 消息的复制和重试操作。待发送图片 chip 使用编辑器共用的 `ImagePreviewOverlay` 打开预览，预览只遍历当前上传队列。发送通过前置校验后立即清空输入文本；Agent 流式请求异常时，session 标记为失败并解除输入锁定。非 JSON 的 500 或网关错误页只显示受控短提示、HTTP 状态和可选请求编号，不向消息区透传 HTML。

未发送的 Agent 输入由 `utils/agentComposerDraft.js` 写入浏览器 IndexedDB。文本、结构化 Mention 片段和 Mention 元数据与待发送媒体的 Blob、类型、来源和 `upload_order` 一起保存；恢复时重建 contenteditable 内的 Mention 卡片、`File` 对象和图片对象 URL。发送时前端同时提交 `attachments`、`images` 和完整 `media_items`，服务端合并去重并再次按标记、MIME、扩展名分流；只含图片时前端补入“分析图片并说明可确认内容”的默认任务。服务端落库用户消息、创建 session 后立即发出 `session_created`，回传真实消息 ID、会话归属、受控图片引用和预览 URL，让前端立刻回显 prompt 和图片并清空草稿。附件解析和图片识别随后在同一条 SSE 任务中执行；成功摘要以 `image_recognition` 分类写入与解析附件相同的持久化来源层，并保存受控图片引用，且作为首个 Agent 用户消息的明确上下文。后续同一对话自动加载这段文本，不让 Agent 通过图片工具重新读取原图。该记录没有过期时间，不提前上传服务端；上传或建会失败则保留并恢复发送前输入。

## 3. 文件 Mention

`@` 的对象是文件，不再是文章文本块。

1. 前端从工作区文件树生成文件和目录候选，按标题、名称、路径匹配。
2. 用户选中后得到结构化 mention，输入框在光标处显示不可编辑的内联卡片，文本不暴露 `@{相对路径}`。
3. 消息元数据保存 `id / type / name / path`；内部 Agent goal 生成等价 token，供 Prompt 识别为显式文件或目录定位。
4. Agent 需要正文时调用 `read_file`；目录先调用 `analyze_folder`。Mention 本身不附带文件全文。
5. 历史 token 在读取时兼容转换为卡片。卡片预览只按需读取当前文件正文，目录不会一次性加载全部正文。
6. 未 Mention 时，模型根据任务决定是否分析目录、检索知识库或读取文件。
7. Mention 只提供显式上下文，不参与普通任务的发送门槛。输入框递归读取浏览器生成的文本和换行节点；删除 mention 后会恢复可编辑文本节点和选区，用户可继续输入或直接发送。

## 4. Agent Loop

文件工作区使用现有 `/api/agent/loop/start`、session、SSE、预览和会话数据。

- 新任务的 `goal` 只包含用户任务，不包含当前打开文件、路径和画布块快照。
- 系统仍不把当前打开文件当作隐式目标；但本轮出现重写、改写、润色、修订、更新或续写等承接语，且同一对话存在最近创建文件时，会从 operation set 传入真实文件路径、操作集 ID 与状态。Agent 先读该目标并使用全文修订预览，工具表不提供 `create_note`；明确另建文件时不启用这条限制。
- 同一对话存在最近文章候选、当前又是写作任务但未说明新建或改写目标时，session 创建后直接生成提问卡片。候选文章和“新建一篇文章”是明确选项；回答写入当前 session，选择已有文章后只允许 `read_file` 和 `preview_file_revision` 的承接路径。唯一候选且明确“继续修改”继续使用原有直达流程。
- 文件写入权限为工作区根目录内的非删除 `create/modify`。
- 单文件修订使用完整草稿预览，批量正文修改和目录操作各自使用对应预览工具。
- `preview_canvas_blocks` 和 `@bN` 块级协作不再注册给 Agent。
- 历史会话暂时继续用 `kind=canvas` 保存，保证已有 Agent 会话可恢复；这是存储兼容层。

### 4.1 Skill 与 MCP 扩展

- 输入框的 `@` 候选在文件和目录之外增加有效 Skill。Skill Mention 的内部 token 是 `@{skill:<skill-id>}`，它不参与文件路径解析；创建 session 时单独写入 `skill_mentions`。
- Agent 获得的是有效 Skill 的摘要目录，明确 Mention 的 Skill 必须先加载；模型只有在任务相关时才应加载其他 Skill。加载后的正文和支持文件均不可信，无法修改 Agent 的上层规则。
- MCP 选择作为本次发送参数保存，并同时构成当前任务的 Server 授权。关闭时不注册 MCP 工具；指定模式只注册一个已启用 Server；自动模式仅在已启用 Server 的缓存工具中做受限匹配。缓存超过 5 分钟时，服务端先尝试刷新对应 Server 的工具列表；失败不阻断任务，保留上次成功缓存。任务结束后不保留授权，已停用或不存在的指定 Server 自动回退为关闭。
- MCP 不再使用 Server/工具策略和逐工具授权交互；旧策略字段只保留数据库兼容。MCP 返回内容仍按外部不可信输入处理。
- MCP 输入控件的可用性只看“当前运行环境可见且已启用”的 Server 数量，不以连接成功或工具缓存为前置条件。设置保存、停用、删除会派发浏览器事件；工作区在挂载、窗口聚焦和事件触发时刷新，最后一个 Server 消失后立即关闭自动模式。
- 全局 Agent 文件统一位于应用数据目录的 `agent/`：`soul.md` 作为长期人格，`memory.md` 保存跨会话偏好和确认决策，`style.md` 只服务写作。文件正文是唯一来源，设置页、Prompt 与工具共用受 Hash 保护的服务；用户文件始终低于系统安全和确认规则。
- Agent 还可通过 `install_skill_from_git` 直接安装无凭据 HTTPS Git Skill，或通过 `add_mcp_server` 新增并测试 MCP。配置完整即执行，不走提问卡片；Skill 同名和 MCP 同名都拒绝覆盖。HTTP MCP 全端开放，stdio MCP 仅 Electron 开放。Agent 传入的 Header/env 强制存入密钥库，运行日志、SSE 和工具结果只输出脱敏摘要；原始用户对话按会话留存策略保存。
- Skill 设置页的 ZIP 导入使用既有受管安装事务：前端只提交单个 `.zip` 文件及冲突策略，不传入安装路径；服务端完成隔离解压、安全校验、候选扫描、安装和索引。默认冲突策略拒绝同名目录，用户明确开启覆盖后才替换同名受管 Skill。当前安装记录为 Git 的受管 Skill 可手动更新：服务端用原仓库拉取 `main` / `master`，要求 `name` 不变，并通过 staging/备份目录替换，失败不修改已有 Skill。启停、扫描、安装或更新成功时，设置页派发变更事件；当前文件工作区立即重新拉取启用且有效的 Skill，使 `@` 候选无需刷新页面即可同步。
- 文件工作区将当前有效 Agent 对话 ID 持久化到浏览器端。下次打开时仅在历史列表仍含该 ID 时恢复对话；新建、删除当前对话、失效或详情读取失败都会清除记录。

### 4.2 对外 MCP 调用

- Notus 作为外部 MCP Server 时，和“内部 Agent 调用用户配置的 MCP Server”完全分离：外供端点固定为 `/api/mcp`，只接受 Bearer Token，并按该 Token 的权限注册工具；设置管理接口固定为受保护的 `/api/settings/mcp/*`。懒猫只放行外供端点，避免平台 OAuth 解析 MCP Token 或扩大管理接口暴露面。
- Token 可独立设置自动应用或手动确认；基础只读工具默认开启，写入工具默认关闭。`get_change_status` 只在手动确认 Token 中可授权和注册，自动 Token 会在服务端剔除该权限。`search_files` 只匹配文件名和相对路径，不走知识库检索；Skill 和 MCP Server 只返回经过脱敏的摘要。
- MCP 设置页用“调用 MCP”和“MCP 服务”两个标签区分 Notus 调用外部 Server 与外部 Agent 调用 Notus，避免把两套配置和凭据混在同一资源列表中。
- 对外写入不开放删除。所有写入先检查 `expected_hash`，局部修改还检查 `old`；自动模式直接应用，手动模式持久化为独立外部变更，设置页审核后再应用或拒绝。外部变更不绑定 Agent 会话，也不会占用 Agent operation set。

## 5. 检索与索引

向量、FTS、标题命中、文件系统读取和增量索引仍保留。它们从独立知识库页面能力变为 Agent 的按需工作区工具能力。

`search_knowledge` 适合正文、事实材料和语义参考；目录存在性、目录移动和新建目录目标使用 `analyze_folder` 获取实时结构。

`search_knowledge` 和用户开启后可用的 `web_search` 均由服务端执行 3→5 查询计划，模型传入的原始词固定排在首位。首轮 3 项中没有充分证据时才补 2 项；知识库和联网来源分别按 session 限制到 5 项，重复调用和换词读取缓存。显式 URL 在输入解析阶段直连读取，与联网搜索开关无关；成功回执不可被后续空搜索覆盖，空搜索只表示没有补充结果。

每个查询、命中资料、显式 URL、文件读取和写入状态都会生成脱敏回执。最终 assistant 消息由服务端写入资料和文件摘要；“已使用资料 / 文件变更”卡当前由 `AGENT_TASK_RECEIPTS_ENABLED = false` 暂时关闭，模型正文不负责报告工具完成状态。用户追问关键词、README 或工具执行情况时，Agent 调用只读 `get_task_activity` 仍返回当前 session 的真实记录。

## 6. 兼容边界

`/knowledge` 和 `/canvas` 仅作跳转。旧 API、索引、会话、风格和预览数据不强制迁移或删除，避免旧数据丢失。后续新 UI 与新 Prompt 不再依赖画布 block 模型。

## 7. 图片存储与对话图片整理

编辑器粘贴和工具栏选图统一进入 `/api/files/:id/images`。Agent 对话图片先保存为会话临时文件；写入笔记时，`notus-conversation-image` 受控引用按所属会话解析，拒绝跨会话图片和客户端路径。两条业务链路共同调用 `lib/imageStorage.js`，按图床设置写入本地资源目录或对象存储。

对象存储模式支持 COS、OSS、R2。服务端持有密钥并生成 SHA-256 对象键，Markdown 只保存公开 URL。上传错误不会生成图片节点或写入笔记，也不会自动改为本地资源；临时上传文件始终删除。远程 URL 继续由既有图片缓存和索引链路按需处理。

图片写入预览只保存临时引用。应用前先检查文件未变化，再复制图片、替换 Markdown 地址，并把图片新增、移除、替换同步到 operation set 的 `media_changes`。DiffDialog 直接显示图片缩略图和 Markdown 文件路径；点击路径会先关闭弹窗，再打开对应文档。文件不存在或已经打开时通过提示反馈，不触发额外切换。回滚只恢复 Markdown，不物理删除资源。

Agent 会话图片位于 `<sessionDir>/images`，文件通过消息元数据和所属会话关联。当前没有会话结束或删除后的自动清理任务，临时文件会继续保留以支持历史图片读取；上传失败产生的中间文件会立即删除。应用时生成的本地资源或对象存储对象不依赖临时文件生命周期。
