# Notus 桌面端路线图

> 最后更新：2026-05-01
> 作用：作为 Notus 桌面端后续开发、验证和迭代的唯一主文档来源。

---

## 1. 文档说明

### 1.1 作用

本文件统一记录桌面端的当前基线、未完成项、优先级、验收口径、已知限制、风险和每轮迭代记录。

### 1.2 维护规则

- 新增或调整桌面端功能时，先更新本文件。
- 如果本轮改动改变了总体完成度，再同步更新 `docs/PROGRESS.md`。
- `docs/TODO.md` 不再维护桌面端细项，只保留非桌面 backlog，并保留本文件入口。
- 如果改动属于正式需求，仍需先更新 `Requirements/LEDGER.md`。
- 如果是 bug，仍只写入 `docs/BUG_TRACKER.md`，不要混入本文件。

### 1.3 与其他文档的关系

- `docs/PROGRESS.md`：只保留桌面端阶段摘要和里程碑状态。
- `docs/TODO.md`：只保留非桌面 backlog。
- `Requirements/`：记录桌面端新增需求、功能优化和体验优化。
- `docs/BUG_TRACKER.md`：记录桌面端 bug，不记录路线图和待办事项。

## 2. 当前已完成基线

### 2.1 Electron 壳与托管工作区

- 已完成本地 Next standalone 服务启动，由 Electron 壳负责拉起和承载。
- 已完成应用内托管工作区，笔记、附件、数据库、日志和会话目录统一写入应用专属目录。
- 已完成首次启动自动建目录，目录结构已经由桌面壳统一管理。

### 2.2 桌面桥接与平台中间层

- 已完成 `window.notusDesktop` 预加载桥接。
- 已接入 `getProfile`、`pickImportSource`、`openDataDirectory`、`clearLocalDataAndQuit`。
- 已完成平台中间层，当前通过统一入口处理运行目标识别、路径解析和能力清单。

### 2.3 数据清理与基础桌面操作

- 已提供“打开数据目录”菜单项。
- 已提供“清除本机数据并退出”菜单项。
- Windows 安装包配置已经打开 `deleteAppDataOnUninstall`，但仍需真实卸载回归验证。

### 2.4 打包与分发基础

- 已有桌面开发命令：`npm run dev:desktop`、`npm run dev:desktop:all`。
- 已有桌面构建命令：`npm run build:desktop`、`npm run dist:desktop`。
- 已补充显式桌面打包命令：`npm run dist:desktop:mac:x64`、`npm run dist:desktop:mac:arm64`、`npm run dist:desktop:win:x64`。
- 已有 Web 分发命令：`npm run dist:web`。
- 已有懒猫 `.lpk` 打包命令：`npm run dist:lpk`。

### 2.5 当前快捷键状态

- Web 端和 Electron 端都已支持页面内快捷键。
- Electron 端已补充首版运行时系统级快捷键 `CommandOrControl+K`，可唤起主窗口并直接打开搜索。
- 当前系统级快捷键只覆盖固定搜索入口，不跟随设置页里的自定义值变化。
- 应用完全退出后，当前版本仍不支持通过快捷键重新启动应用。

## 3. 未完成功能路线图

## P0

### 3.1 Windows NSIS 卸载后自动清理真实回归

- 优先级：P0
- 状态：待验证
- 类型：已接入但未实机验证
- 目标：确认 Windows 安装、运行、卸载后，Notus 托管数据目录能够按预期清理，不在用户主机上残留数据库、附件和日志。
- 当前缺口：当前只有 `electron-builder` 配置和代码层清理入口，缺少真实安装机上的完整回归记录。
- 验收口径：
  - 安装后能够正常启动和写入托管目录。
  - 卸载后应用目录与托管数据目录一并清理。
  - 卸载后重新安装，不会读到旧数据库或旧会话。
- 关联模块：`package.json`、`desktop/main/index.js`、`desktop/shared/paths.js`

### 3.2 macOS DMG 安装、手动清理再删除应用的完整回归

- 优先级：P0
- 状态：待验证
- 类型：已接入但未实机验证
- 目标：确认 macOS 下 DMG 安装、运行、执行“清除本机数据并退出”、再删除应用的完整流程可用。
- 当前缺口：当前只有代码路径和菜单入口，缺少真实设备上的安装、清理和删除应用回归。
- 验收口径：
  - DMG 安装后应用能够正常启动。
  - “清除本机数据并退出”能够删除托管目录内容。
  - 删除应用后，本机不保留 Notus 的业务数据目录。
- 关联模块：`package.json`、`desktop/main/index.js`、`desktop/preload/index.js`

### 3.3 桌面端与 Web 端的功能一致性回归清单

- 优先级：P0
- 状态：进行中
- 类型：已接入但未完整验证
- 目标：确保桌面端与 Web 端在现有业务能力上表现一致，不因桌面壳引入行为差异。
- 当前缺口：虽然主业务代码复用同一套 Next.js 逻辑，但缺少一份覆盖知识库、文件、创作、设置和 SSE 的完整回归清单。
- 验收口径：
  - `/setup`、导入、索引、知识库问答、创作页、设置页在 Web 与 Electron 下都可正常使用。
  - 平台专属接口在 Web 下自动降级，在 Electron 下可正常调用。
  - 页面中不再依赖硬编码桌面路径或桌面环境判断。
- 关联模块：`notus/pages/`、`notus/contexts/PlatformContext.js`、`notus/utils/platformClient.js`、`desktop/`

## P1

### 3.4 系统级快捷键扩展

- 优先级：P1
- 状态：进行中
- 类型：已接入首版，后续仍需扩展
- 目标：在现有首版系统级快捷键基础上，继续评估更多桌面级动作、冲突处理和是否与设置页自定义值联动。
- 当前缺口：当前只支持固定 `CommandOrControl+K` 打开搜索，还没有多动作方案，也没有和设置页快捷键联动。
- 验收口径：
  - 明确哪些快捷键保留为页面内，哪些继续升级为系统级。
  - 首版固定搜索快捷键保持可用，不因后续扩展带来回归。
  - 如果未来支持联动设置页，需要补齐主进程注册更新和冲突处理。
  - Web 端仍保持现有快捷键行为，不因桌面能力引入回归。
- 关联模块：`desktop/main/index.js`、`notus/contexts/ShortcutsContext.js`

### 3.5 原生菜单补齐常用桌面命令

- 优先级：P1
- 状态：未开始
- 类型：架构已预留但未实现
- 目标：在当前基础菜单之上，补齐更符合桌面应用习惯的常用命令。
- 当前缺口：现有菜单只覆盖基础数据目录、清理、编辑和窗口操作，缺少导入、打开最近、刷新工作区等常用入口。
- 验收口径：
  - 菜单中补齐至少一组高频桌面命令。
  - 菜单命令与页面内操作一致，不生成两套不一致入口。
  - Web 端不受影响。
- 关联模块：`desktop/main/index.js`

### 3.6 打开最近工作区 / 最近导入目录

- 优先级：P1
- 状态：未开始
- 类型：尚未设计也未实现
- 目标：为桌面端补充最近使用记录，减少重复导入和重复定位目录的操作。
- 当前缺口：当前托管工作区只有固定应用目录，没有“最近使用来源”的记录模型、展示入口和清理规则。
- 验收口径：
  - 能记录最近导入的目录或文件来源。
  - 能从菜单或界面重新打开最近记录。
  - 记录失效时有清晰提示，不影响主流程。
- 关联模块：`desktop/main/index.js`、`desktop/preload/index.js`、`notus/utils/platformClient.js`

### 3.7 桌面通知能力

- 优先级：P1
- 状态：未开始
- 类型：尚未设计也未实现
- 目标：为索引完成、导入结束、长任务失败等场景提供原生桌面通知能力。
- 当前缺口：当前只有页面内提示，没有桌面通知接口、权限处理和通知策略。
- 验收口径：
  - 至少覆盖一类后台任务结束通知。
  - 通知内容与页面内提示保持一致，不重复制造噪音。
  - Web 端继续使用原有页面提示，不强行引入桌面分支。
- 关联模块：`desktop/main/index.js`、`desktop/preload/index.js`、`notus/components/ui/Toast.js`

## P2

### 3.8 托盘与最小化常驻

- 优先级：P2
- 状态：未开始
- 类型：尚未设计也未实现
- 目标：评估是否需要为桌面端提供托盘入口和最小化常驻能力。
- 当前缺口：当前关闭窗口即退出应用，没有托盘、常驻状态和相关交互设计。
- 验收口径：
  - 明确是否启用托盘模式。
  - 如果启用，需提供退出、显示主窗口、数据状态说明等基础能力。
  - 不影响当前默认的退出和清理逻辑。
- 关联模块：`desktop/main/index.js`

### 3.9 自动更新

- 优先级：P2
- 状态：未开始
- 类型：尚未设计也未实现
- 目标：为桌面安装包补充自动更新策略和版本提示能力。
- 当前缺口：当前只有手动构建和手动分发，没有更新源、版本检查、回滚和失败提示机制。
- 验收口径：
  - 明确更新来源和签名策略。
  - 至少完成更新检查与用户提示的产品设计。
  - 不影响现有离线安装包交付方式。
- 关联模块：`package.json`、`desktop/main/index.js`

### 3.10 文件关联 / deep link

- 优先级：P2
- 状态：未开始
- 类型：尚未设计也未实现
- 目标：评估桌面端是否需要支持文件关联、协议唤起或 deep link。
- 当前缺口：当前没有文件关联注册、参数处理和安全边界。
- 验收口径：
  - 明确要支持的文件类型或协议范围。
  - 补齐主进程参数处理与安全校验。
  - 不影响 Web 端现有路由和导入流程。
- 关联模块：`package.json`、`desktop/main/index.js`

### 3.11 桌面端专属诊断信息页

- 优先级：P2
- 状态：未开始
- 类型：架构已预留但未实现
- 目标：补充一个桌面端诊断页，集中展示运行目标、数据目录、平台能力、版本信息和常见自检结果。
- 当前缺口：平台中间层已经能返回部分运行信息，但缺少前端可见的集中诊断页面。
- 验收口径：
  - 页面能够展示平台 profile、能力清单和关键路径信息。
  - 能帮助确认当前运行在 Web、Electron 还是 Lazycat。
  - 不泄露不必要的本机敏感信息。
- 关联模块：`notus/contexts/PlatformContext.js`、`notus/utils/platformClient.js`、`notus/pages/settings/`

## 4. 桌面端专项验证

### 4.1 Windows 安装 / 卸载 / 数据清理

- 验证安装包可以正常安装和启动。
- 验证导入、索引、问答、创作、日志落盘都能正常工作。
- 验证卸载后托管数据目录是否清理干净。
- 验证重装后不会读到旧数据库和旧会话。

### 4.2 macOS DMG 安装 / 手动清理流程

- 验证 DMG 安装和首次启动。
- 验证“打开数据目录”与“清除本机数据并退出”两个入口。
- 验证手动清理后再次启动会自动重建目录。
- 验证删除应用前后，本机不保留业务数据目录。

### 4.3 Web 与 Electron 功能一致性

- 验证 `/setup` 三步引导在两端表现一致。
- 验证文件导入、重命名、删除、导出和图片代理。
- 验证索引状态、SSE 进度、失败重试和清空索引。
- 验证知识库问答、多轮会话、来源定位和设置页模型配置。
- 验证创作页大纲、块编辑、保存、对话恢复和自动保存。

## 5. 已知限制与风险

- 当前快捷键只有页面内能力，尚未提供系统级桌面快捷键。
- 当前桌面壳已有基础菜单，但仍不属于完整桌面交互。
- Windows 与 macOS 的真实安装、卸载和数据清理回归尚未完成。
- 当前首版只支持应用内托管工作区，不支持外部目录直连。
- 一些桌面能力已经有架构位置，但还没有产品设计和实机验证。
