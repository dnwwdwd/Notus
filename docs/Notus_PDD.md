# Notus 产品设计文档（PDD）

> v3.1 · 更新时间：2026-07-19

## 1. 产品定位

Notus 是本地 Markdown 文件工作区与 AI Agent。用户在同一个工作区中管理文件、编辑正文、检索已有资料，并让 Agent 读取、创建或修改文件。

`.md` 文件是唯一真相来源。SQLite 保存索引、会话、预览和运行状态，文件被外部编辑后可重新索引。所有非删除写入都会产生可审查记录；自动确认模式保留回滚入口，手动确认模式等待用户应用。

## 2. 当前产品结构

```text
Notus
├── 顶部工作区控制：搜索、保存、编辑器开关、AI 面板开关、设置
├── 左侧 Sidebar：文件树 / 当前文件目录
└── 文件工作区（/files）
    ├── 富文本编辑器：可选展开
    └── AI 聊天面板：可选展开，可独立于文件使用
```

`/knowledge` 与 `/canvas` 保留兼容跳转到 `/files`，不再提供独立页面、导航入口或独立产品流程。

## 3. 核心体验

### 3.1 文件编辑

- 文件页保留 Tiptap 富文本编辑器与 Markdown 双向转换。
- 选中文件时可同时展开编辑器和 AI 面板；两栏之间可拖动调整宽度。
- 编辑器、AI 面板的展开状态持久化在浏览器。关闭窗口后重新打开时，恢复上次选中的文档和两者的开关组合；切换已打开文件时不重置状态。
- 用户在已运行的工作区从未打开文件状态进入某篇文件时，使用个性化设置中的默认展开值；启动恢复的已选文档不再覆盖保存的面板组合。
- 再次点击当前选中的侧边栏文件会清除当前文档选中状态，编辑器回到未选择文件的空态，AI 面板保持原状态。
- 富文本编辑器工具栏支持通过弹窗自定义行数和列数插入可编辑 Markdown 表格，首行为表头。
- 顶部不显示文件、知识库、创作等产品导航。顶部右侧使用搜索 icon、富文本编辑器和 AI 聊天面板两个无边框控制 icon；三个控制与设置按钮共用 32px 点击区域，搜索提示为“搜索文件”。
- 富文本编辑器和 AI 聊天面板默认快捷键分别为 `Mod+B` 与 `Mod+U`，并可在快捷键设置中修改。
- 文件工作区会记住富文本编辑器和 AI 面板的双栏宽度；AI 输入框默认保持约 5 行文字高度，宽度固定为父容器的 95%；消息列表在底部保留足够空间，复制和重试操作不会被输入区覆盖。
- 工作区不再要求浏览器或桌面窗口维持固定的 `1360 × 800` 尺寸。宽度足够时保留三栏与可拖动双栏；中等宽度收缩侧栏和面板下限；窄于 900px 时编辑器与 AI 面板上下排列；窄于 700px 时侧栏以可展开抽屉呈现。弹窗、设置、图片预览和通知始终限制在当前视口内。
- 富文本编辑区采用独立标题输入区和正文编辑区：标题保存为 Markdown 一级标题，正文编辑器不显示 Notus 系统 Frontmatter。Agent 创建笔记时，标题输入区显示 Agent 生成的标题。
- 导入 Markdown 时，文件标题默认使用导入文件名，并同步到一级标题和 Frontmatter `title`；导入不会因标题—文件名绑定而再次改名。
- AI 聊天面板的回底按钮始终位于输入区上方；图片预览覆盖层覆盖顶栏，关闭和图片名称可正常操作。
- 设置在当前工作区上方以弹窗展示，点击遮罩不关闭；弹窗内部标题栏不重复显示“设置”，仅保留关闭按钮。模型、搜索、Skill、MCP、日志、个性化、图床、存储、快捷键、关于共用 860px 最大内容列和统一的页面标题样式，顶部只显示标题名称。Skill 与 MCP 使用资源卡展示状态、元信息和操作；个性化页使用与搜索配置相同的全宽设置区。
- “复制全文”复制 Markdown 源文本；本地图片路径保持 Markdown 原值，不将图片转为 Base64 写入剪贴板。
- 粘贴或插入的新图片可按图床设置保存到本地资源目录，或上传至腾讯云 COS、阿里云 OSS、Cloudflare R2。云端模式将公开 URL 写入 Markdown；上传失败时不插入图片。

### 3.2 AI Agent

- AI 面板可以在未选中文件时直接发起对话、创建笔记、整理目录或检索工作区。
- AI 面板顶栏不显示品牌标题；无消息时只展示“你今天在想些什么？”。
- Agent 任务不会把当前打开文件作为默认目标，也不会自动读取当前文件。
- 同一对话中，用户以“重写”“改写”“润色”“更新”等承接语继续处理前一轮新建笔记时，系统从该对话最近的真实创建操作中恢复文件路径；Agent 必须先读取该文件并生成修订预览，不会再次新建同主题笔记。用户明确要求另建文件时，才恢复新建能力。
- 用户可通过 `@` 搜索工作区文件和目录。候选主行展示文件名或目录名，次行展示一次相对路径，文件使用 `Icons.file`、目录使用 Sidebar 展开状态的 `Icons.folderOpen`，按标题、名称和路径做模糊匹配；选中后在光标处生成不可编辑的内联 mention 卡片，不在可见文本中暴露 token。
- mention 在消息数据中保存 `id / type / name / path`，并保存文字与 mention 的交错顺序；输入框和用户历史消息复用同一张紧凑卡片。目录卡片使用 Sidebar 展开状态图标。点击文件卡片可预览 Markdown，点击目录卡片可浏览目录内笔记并按需读取正文。
- Mention 是可选上下文。普通文本、图片或解析附件无需引用任何文件或目录即可发送；用户删除 Mention 后，输入框继续保留可编辑光标并可直接发送普通任务。
- 内部 Agent 上下文使用 `@{相对路径}` 表示明确文件定位，使用 `@{folder:相对路径}` 表示目录范围。Agent 对文件在需要正文时调用 `read_file`；对目录先调用精确路径的 `analyze_folder`，再按任务读取少量文件或限定目录检索。目录引用不会默认扫描整个工作区。
- 未 Mention 文件时，Agent 根据任务决定是否使用 `analyze_folder`、`search_knowledge` 或 `read_file`。普通对话无需为了查找文件而调用工具。
- 输入支持解析附件、图片、联网搜索、模型选择、自动/手动确认、历史对话、消息复制/改写/重试、提问卡片和 diff 详情。图片不属于附件：单条消息最多 30 张、单个对话最多 50 张；解析附件单条最多 10 个、单个对话最多 20 个。两类媒体按上传顺序显示在同一组 chip 中；待发送图片 chip 可打开与笔记编辑器共用的全屏预览，并在当前上传队列内切换。
- 当前轮图片进入当前 Agent 请求。OpenAI Chat Completions 与 Anthropic Messages 分别按各自视觉输入协议组装上下文；历史图片不会自动重复注入，Agent 需要时通过会话图片工具选择后再读取。
- 未发送的 AI 输入草稿长期保存在当前浏览器的 IndexedDB 中，包含文本、Mention 及其顺序、待发送图片和解析附件；刷新页面或重新进入工作区后恢复，不设置过期时间。服务端创建 Agent session 并持久化用户消息后，输入文本、图片、附件和草稿同步清理；在此之前上传或建会失败则保留草稿。
- 文件工作区同时保存当前打开的有效 Agent 对话 ID。应用重新打开时，先读取历史列表；该会话仍存在才恢复消息、待处理预览和交互状态，记录失效、读取失败、新建或删除当前会话时清除该 ID。
- 用户要求把当前或历史对话图片整理进笔记时，`@` 文件、明确路径、当前输入或最近对话能唯一确定目标才直接生成预览。当前编辑器打开的文件不构成隐式目标。
- 目标不唯一时，Agent 检索后以提问卡片给出最多 3 个候选，并提供“手填已有路径”和“新建笔记”；只有选中后两项才填写 Markdown 相对路径。已确定笔记但未指定位置时，Agent 写入语义匹配的小节；没有匹配时在文末新增“调研图片与整理”。
- 提问卡片的前后题导航使用无文字箭头 icon；单选答案会自动进入下一题，文本输入时保留方向键的原生编辑行为。回答全部可见问题后，卡片在同一组件内列出全部问题与答案，用户可逐项修改并直接提交续跑。

### 3.3 写入与工具边界

- 工具集：`search_knowledge`、`read_file`、`list_conversation_images`、`read_conversation_images`、`create_note`、`preview_file_revision`、`preview_patch_files`、`preview_file_operations`、`ask_question_card`、`analyze_folder`、`check_links`，以及用户开启联网搜索后可用的 `web_search`。
- Agent 可以创建、修改、重命名和移动 Markdown 文件或目录；删除文件和目录不开放。
- 单文件大范围修改优先走 `preview_file_revision`，由代码生成 diff 并校验 hash。
- 小范围或多文件正文修改使用 `preview_patch_files`；文件和目录操作使用 `preview_file_operations`。
- 对话图片在预览阶段以 `notus-conversation-image` 受控引用保留在 Markdown 草稿中。应用预览前先校验文件未 stale，再按图床设置复制到本地资源目录或 COS、OSS、R2，最后写入相对路径或公开 URL。
- 图片新增、移除、替换随 operation set 保存。DiffDialog 在文本 diff 上方直接显示新增图、移除图，或并排显示替换前后的图片。回滚只恢复原 Markdown，不删除本地资源或对象存储对象。

### 3.4 桌面端 Skill 与 MCP

- 桌面端会发现本机与 Notus 管理目录中的有效 Skill。输入 `@` 时，文件、目录和 Skill 使用同一候选菜单；明确选择的 Skill 只绑定到本次 Agent session，不自动读取其正文。
- Agent 可以根据用户明确选择或当前任务，从受控目录调用 `load_skill`，再按 Skill 的明确引用调用 `read_skill_file`。Skill 文本仅作为任务参考，不能改变 Agent 的安全、数据访问或确认规则。
- MCP 输入入口位于 Agent 输入框右侧，可关闭、自动选择或固定到单个 Server。自动模式只从已启用 Server 的已发现工具中按任务描述选择，不代表无条件允许调用。
- MCP 工具默认在调用前展示授权卡。用户可只允许当前一次、允许整个当前任务、设为以后默认允许或拒绝；拒绝的工具不能由 Agent 通过其他调用绕过。
- stdio MCP 与本机外部 Skill 扫描仅在 Electron 桌面端可用。Web 与兼容运行时只使用其管理目录和 Streamable HTTP MCP。
- Skill 使用书册星标图标，MCP 使用双节点 Server 图标，快捷键使用键盘图标；这些图标在设置导航、设置页、输入控件、Mention 与授权卡中保持一致。
- 会话图片临时文件保存在 `<sessionDir>/images`，通过消息元数据与会话逻辑绑定。当前策略不因 Agent 完成、取消、过期、回滚或笔记应用而自动销毁；删除会话记录也不会物理删除临时文件。上传失败产生的中间文件会清理，已写入笔记的永久资源独立保留。
- `@b1` 等画布块引用和 `preview_canvas_blocks` 不属于当前产品能力。

## 4. 主要用户流程

### 4.1 直接与 AI 协作

1. 用户打开 `/files`，无需选择文件。
2. 在右侧 Agent 输入任务。
3. Agent 只在任务需要时读取、检索或分析目录。
4. 需要写入时生成预览，按确认模式应用，并刷新文件树与当前编辑器。

### 4.2 编辑文件并与 AI 协作

1. 用户从文件树选择 Markdown 文件。
2. 系统按个性化默认值展开编辑器和 AI 面板；同一轮后续文件切换保留当前面板状态。
3. 用户编辑正文，保存后触发增量索引。
4. 用户在 AI 面板输入任务，可用 `@` 引用任意工作区文件或目录，也可上传图片和解析附件。
5. 若当前编辑器有未保存内容，发送 Agent 任务前先保存，避免 Agent 读取旧文件版本。
6. 输入中的文本、文件 Mention、图片和解析附件会持续保存在浏览器草稿中；服务端创建 session 并接收用户消息后立即清理，上传或建会失败时保留，浏览器刷新不会丢失未完成任务。

### 4.3 文件与目录 Mention

1. 用户输入 `@` 或部分文件名。
2. 输入框按文件名、目录名、标题和路径过滤工作区节点。
3. 候选项主行显示名称、次行显示路径，支持上下键、回车和 Esc。
4. 文件或目录选中后在当前位置插入结构化 mention 节点，并以可删除、可预览的紧凑内联卡片展示。
5. Agent 内部接收等价 token；对文件按需要调用 `read_file`，对目录先调用精确路径的 `analyze_folder`，再在目录范围内选择少量文件读取或检索。

### 4.4 对话图片整理进笔记

1. 用户在调研或问答时上传图片，并要求整理进某篇笔记。
2. Agent 使用当前轮图片，或从历史图片清单中按需读取少量图片；不会把整段会话图片重新送入模型。
3. 目标明确时，Agent 读取目标笔记并生成完整修订或新建笔记预览。目标不明确时，卡片收集笔记选择和条件路径。
4. DiffDialog 展示文字与图片变更。手动确认和自动确认都在应用时执行图片落盘；任一步失败或文件已变化时，笔记正文保持不变。

## 5. 页面范围

| 路由 | 状态 | 说明 |
|---|---|---|
| `/files` | 主工作区 | 文件树、富文本编辑器、AI Agent 面板 |
| `/knowledge` | 兼容跳转 | 跳转 `/files` |
| `/canvas` | 兼容跳转 | 跳转 `/files` |
| `/settings/*` | 保留 | 模型、搜索、Skill、MCP、个性化、图床、存储、日志、快捷键和关于 |
| `/setup`、`/indexing` | 保留 | 初始化和索引流程 |

## 6. 个性化与持久化

- 个性化设置提供“默认展开富文本编辑器”“默认展开 AI 聊天面板”和图片上传位置。图片上传位置以本地、腾讯云 COS、阿里云 OSS、Cloudflare R2 的分段 tab 展示；未配置的云图床仍可点击，会提示并提供前往配置的链接。
- 图床设置页分别编辑腾讯云 COS、阿里云 OSS、Cloudflare R2 的 Bucket、地域、Endpoint、对象前缀、公开访问基础 URL 与密钥；保存参数不改变图片上传位置。密钥不会在设置页面回显。
- 默认值只在已运行的工作区从无文件状态打开文件时生效。
- 顶部开关、当前文件、当前 Agent 对话和分栏宽度保存在本地浏览器；关闭窗口后重新打开时恢复为关闭前的工作区组合。当前对话仅保存 ID，不保存或改变服务端会话内容。
- AI 输入区的未发送草稿保存在 IndexedDB，不设置过期时间；图片和附件以 Blob 保存，恢复时重新创建浏览器 `File` 对象和预览 URL。该草稿不写入服务端会话，也不跨浏览器同步。
- 侧边栏、文件树展开状态、文件树滚动位置和当前文件仍按原有工作区状态保存。

## 7. 验收标准

1. 用户不选择文件也能发送 Agent 任务。
2. 选中文件后，富文本编辑器与 AI 面板可并排显示并调整宽度。
3. 顶部没有知识库和创作导航，两个面板开关可用且持久化。
4. `@` 可按文件名、目录名和路径匹配，候选显示一次名称和路径；Agent 能精确读取 Mention 文件，或先分析 Mention 目录。
5. Agent 未收到 Mention 时不会将已打开文件作为隐式上下文。
6. 再次点击当前选中侧边栏文件会清除选中状态并移除 `fileId` 路由参数。
7. 工具栏弹窗可自定义表格行数和列数，插入后生成可编辑表格并能写回 Markdown。
8. 复制全文的纯文本内容是 Markdown 源文本，图片不会转成 Base64。
9. 本地和三家对象存储模式均可插入图片；对象存储模式的 Markdown 使用公开 URL，上传失败时不产生图片节点。
10. Agent 能把当前或历史对话图片写入明确笔记，并只在应用时复制图片到用户配置的存储位置。
11. 目标不唯一时，提问卡片能选择候选笔记、手填已有路径或新建笔记；单选自动推进，全部回答在同一张卡片中复核。
12. DiffDialog 能显示图片新增、移除和替换；回滚不会物理删除图片资源。
13. 刷新文件工作区后，AI 输入文本、Mention 顺序、待发送图片和解析附件仍可继续编辑；发送成功后浏览器草稿被清理。
14. 在 1366、1024、768 和 390px 宽度下，工作区、设置和通用弹窗不由 Shell 产生页面级横向溢出；宽表格、代码块和 diff 仅在自身内容区横向滚动。
15. 关闭并重新打开应用后，仍存在的当前 Agent 对话自动恢复；Skill、MCP 和快捷键入口使用各自的语义图标，Skill/MCP 设置页不显示顶部说明段落。
