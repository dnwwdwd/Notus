# Notus 产品设计文档（PDD）

> v2.2 · 单一事实源 · 定义产品是什么、为谁做、解决什么问题、长什么样

---

## 1. 产品定位

### 1.1 一句话

Notus 是一个以本地 Markdown 工作区为中心的 AI 知识与写作协作环境：它保留 Obsidian 式的文件可见、可编辑、可被外部工具管理的工作方式，同时逐步引入类似 Claude Code / Codex 的工作区 Agent 能力，让 AI 能在用户授权的范围内阅读、分析、生成预览并修改 Markdown 文件。

### 1.2 核心价值

| 用户需要 | Notus 的解法 |
|------|-------------|
| 希望长期保留自己能直接掌控的 Markdown 工作区 | `.md` 文件是唯一真相来源，SQLite 只保存索引、缓存、状态和历史 |
| 希望 AI 理解整个写作工作区，而不是只回答当前输入 | 基于文件树、当前文件、选定范围、检索证据、对话历史和风格画像构建工作区上下文 |
| 希望 AI 能像协作者一样修改文件，但不能绕过审查 | 所有写入类操作先生成 diff 预览，由用户确认后再落盘 |
| 希望历史文章成为 AI 的长期参考 | 以风格指纹、全局画像、相关原文摘录和检索证据共同支持写作 |
| 希望兼容外部工具、Git 和多端同步 | 文件系统优先，数据库可重建；外部编辑通过监听和对账同步索引 |

### 1.3 不是什么

- 不是只会回答问题的知识库聊天框
- 不是只会对当前文件做普通改写的文本工具
- 不是完整复刻 Obsidian 插件生态的笔记应用，不以数据库视图、看板、日历为主线
- 不是绕过用户审查的后台自动执行 Agent；所有重要读取范围和写入结果都要对用户可见
- 不是云服务，无账号体系，不支持多人协作

### 1.4 设计原则

- **文件优先**：`.md` 文件是唯一真相来源，SQLite 只存索引，可随时重建
- **工作区优先**：AI 的操作对象不是单条消息，而是用户明确选择的文件、目录、当前文档和相关 Markdown 工作区上下文
- **块级协作**：AI 通过 str_replace + Block ID 定位；全文级和多文件级能力也必须拆成可审查的局部修改
- **单索引优先**：知识库长期保持单索引，不做文档摘要索引、章节摘要索引和句级持久索引
- **检索质量优先**：查询规划 + 混合检索（向量 + FTS5 全文）+ 标题命中 + 章节证据扩展 + 条件重排
- **预算感知**：所有主要 LLM 调用按模型上下文窗口裁剪历史、证据和相关块，必要时自动 compact
- **范围可见**：检索范围、写入范围和风格参考范围必须是产品状态，用户能看到、能调整，不交给模型静默推断
- **可审查写入**：创建、改写、移动、重命名、批量整理等写操作都必须先形成预览或明确确认
- **降级友好**：Embedding API、图片 fetch、jieba 加载失败均不阻塞主流程
- **风格学习**：以用户历史文章的离线风格指纹和全局画像为主，而不是只在运行时临时抓 few-shot 片段

## 2. 目标用户

**核心画像：** 有大量 Markdown 文章积累的个人创作者、研究者或工程写作者，希望像管理本地代码仓库一样管理自己的笔记和文章：文件可被 Git、编辑器和外部工具直接处理，同时希望 AI 能理解工作区、生成可审查的修改，并辅助长期写作。

**典型场景：**
- 写了很多技术教程，想用历史文章的知识和风格辅助写新文章
- 查阅自己以前写过的某个主题，记不清在哪篇文章
- 对现有文章某段落不满意，想让 AI 按自己的风格改写
- 让 AI 阅读某个目录下的多篇笔记，整理成专题文章或写作计划
- 让 AI 检查多篇文章之间的重复、断裂、待补充内容，并生成可应用的修改建议

## 3. 产品结构

长期产品结构以 Markdown 工作区为中心，文件管理、知识库问答、创作画布和工作区 Agent 共享同一套文件系统、索引、会话和预览机制：

```
┌──────────────────────────────────────────────────┐
│                      Notus                        │
├──────────────┬──────────────┬────────────────────┤
│   文件管理    │   知识库问答  │    AI 创作画布      │
│   (工作区)   │   (检索)     │    (写作协作)       │
├──────────────┴──────────────┴────────────────────┤
│        工作区 Agent：读文件、分析范围、生成预览、应用确认       │
└──────────────────────────────────────────────────┘
           共用：Markdown 文件系统 + 索引 + 会话 + diff 预览
```

九个页面（见 §6.3）。

## 4. 核心功能一览

### 4.1 文件管理（编辑器）

- 两栏布局：Sidebar（文件树/TOC）+ 所见即所得编辑器
- 基于 Markdown 双向转换的所见即所得编辑体验，还原 Typora 写作手感
- 所见即所得编辑器支持直接粘贴常见 Markdown 语法，并在编辑态即时识别标题、列表、任务列表和 GFM 表格；当剪贴板同时带有 HTML 与纯文本，且纯文本包含 `$...$` / `$$...$$` 数学公式时，优先按 Markdown 解析，保证首次粘贴就直接渲染
- 所见即所得编辑器支持 `$...$` 与 `$$...$$` 数学公式，统一用 KaTeX 渲染；点击现有公式可直接修改 LaTeX 内容
- 所见即所得编辑器中的图片支持直接粘贴本地剪贴板图片，也支持点击放大预览；连续粘贴时不能出现“先闪一下再丢失”的情况，切换范围限定在当前文档，支持左右方向键切换和 `Esc` 关闭
- AST 实时解析生成 TOC，覆盖 H1~H6，点击跳转并随滚动高亮当前章节；文件切换后需要等编辑器真实标题节点稳定再刷新，不能把已有标题误判成“当前文档没有标题”
- 编辑器中已有 Markdown 文档的 GFM 表格需要正确还原为可编辑表格；在所见即所得里直接输入完整的 Markdown 表格语法后，也应自动转成真实表格节点，并显示清晰的外框、单元格边框、表头背景和选中单元格反馈
- 文件保存自动触发增量索引（hash 比对，未变化则跳过）
- 批量导入（ZIP / 文件夹 / 单文件），SSE 进度推送
- 文件导出在只选中 1 个文档时直接下载原始 `.md`，选中多个文档时再导出 zip；单文件导出需兼容中文文件名
- 来源跳转锚点：URL `#L24-L28` 精确行号定位 + 高亮 3s 淡出

### 4.2 知识库问答

- 对话式布局，流式输出；历史入口收敛为 icon + tooltip，旧会话通过右侧抽屉切换
- 单索引知识库：不做分层摘要索引，依靠查询理解、混合检索和条件重排提高命中质量
- 查询规划 + 混合检索（向量 + FTS5 + 标题命中 + RRF + 章节证据扩展）
- 先判断问题是否足够清晰；如果范围不明确，直接追问，不检索，也不生成事实回答
- 对复杂问题最多只允许一次辅助调用，且只会在“改写”与“重排”之间二选一，再进入主回答
- 严格 RAG：无命中直接说不知道，不触发幻觉
- 文档级上下文：chunk 和 section 只负责定位；真正给模型的正文从文件系统读取 Markdown，数据库中的 chunk 内容只作为检索副本
- 知识库回答会回传本次读取的 Markdown 文档摘要和完整/节选统计，前端展示“本次使用了哪些文件”，但不把完整正文直接发给浏览器
- 回答会基于章节级证据自然作答，不再固定套用“结论 / 整理 / 证据”模板
- 回答模式固定为 `clarify_needed / grounded / weak_evidence / conflicting_evidence / no_evidence`
- 证据偏弱时只输出可确认部分和解释性补充；证据冲突时明确提示不同笔记中存在不同说法
- 当前打开文档优先参与召回，但只做温和优先，不能压过更强的正文证据；参考来源支持自动匹配或手动指定文档范围，但不会切换历史对话
- 支持全局历史会话与新建对话；页面默认进入新对话，不自动恢复最近一条旧会话，当前打开文档只影响优先检索
- 流式回答与 Markdown 展示链路统一支持 KaTeX 数学公式，避免聊天区、预览区和编辑区对同一段内容显示不一致
- AgentWorkspace 中的 AI 回复同样使用 Markdown 富文本流式渲染，支持 GFM、数学公式和代码高亮
- 来源卡片：file_title + heading_path + preview + 行号，点击后在知识库页左侧编辑器定位原文并高亮；检索状态、正文、补充说明和来源卡片共用同一个 AI 回复容器
- 所有可见文档标题统一优先显示文档标题，其次显示去掉 `.md` 的文件名；禁止暴露 `article_xxx`、`notus_xxx`、裸 `fileId` 等内部标识
- 主要 LLM 调用按 `context_window_tokens` / `max_output_tokens` 做预算控制，必要时自动 compact 历史与证据包
- 多模型切换：Embedding 与对话模型独立配置

### 4.3 AI 创作画布

- 左右分栏（35/65）：AI 协作区 + 画布区
- 画布以块（Block）为单位，每块附 Block ID
- 旧的 str_replace block 级能力保留为历史兼容；创作页右侧主输入不再以它作为主入口。
- 创作页主输入统一进入 Agentic Loop：默认自动应用模式会直接启动任务，并在文件级预览生成后自动应用和续跑；用户也可以在创作页输入框切换为手动确认，再确认允许写入路径和检索次数上限。
- 知识库页普通问答继续走 `/api/chat`；写作类任务按保守关键词规则显示同一套 Agentic Loop 任务确认卡。
- 局部改写必须以目标块完整全文为输入和输出边界，未修改部分逐字保留；大文本块不能因为上下文裁剪而把截断内容写入 `old/new`
- 创作主链路为”请求规划器 + 执行器”，规划器每次请求都调用 LLM（`target_resolver` 模式）判断意图、目标块和操作类型，不依赖正则打分；正则只用于无歧义词法提取（`@bN` 显式引用、`全文/整篇` 全局标记），结果作为 LLM 候选上下文；没有明确修改动词时，只有用户明确引用块、承接上一轮编辑建议或使用写入/替换/应用到正文等表达，才偏向直接编辑
- 支持 `@bN`、`@b2 @b3`、`@b2-b5`、自然语言序号、开头/结尾、全文以及上一轮目标块延续
- 对”把/将 A 改为/换成/换为/替换为/替换成 B”以及“`@bN A 换为 B` / `A 改为 B`”这类精准替换短语，LLM 确认 edit 意图且目标唯一时，走字符串精准替换，不重新生成块内容
- 意图判断由 LLM 负责：含修改动词或替换句式 → edit；明确提问讨论 → text；明确分析诉求 → analyze；LLM 调用失败时保守返回澄清卡片
- 助手消息会记录最近目标块、最近操作类型、最近建议摘要、当前判断摘要和短时纠错状态，用于处理“继续改刚才那段”“按刚才建议改”“不是聊天，是改文档”这类多轮承接
- 创作请求规划固定走“候选召回 + 受控 AI 仲裁 + 风险校验”，只在低置信或高风险场景启用有限 AI 辅助，不改为 AI-first
- “写到文档中”类请求会先按编辑意图处理，并把来源内容区分为 `draft_text / edit_suggestion / analysis_feedback / general_chat`；只有合格正文草稿能直接进入写入链路
- 当主意图、来源、目标位置或写入方式不够稳定时，会在右侧 AI 面板底部抽屉中一次性补问最多 `3` 个问题；抽屉覆盖输入框，采用列表状态布局，不再把卡片和重试提示内联到消息流里；答完后先进入回顾态，用户点击确认后才续跑，且仍只生成待应用预览
- 如果续跑时原目标块已经失效，不会继续撞 `BLOCK_NOT_FOUND`，而是回退为重新确认写入位置；失败态只保留重试入口
- 高风险预览和澄清后续跑会回显“当前理解”摘要，并提供轻量纠偏入口，支持快速纠正“继续讨论 / 直接改文档 / 目标不对 / 来源不对 / 写入方式不对”
- 事实参考：后台自动补充，始终优先当前文档与相关笔记，不在创作页前台单独展示配置
- 风格来源：自动语义匹配（默认）或手动指定文件；大纲生成和改写统一使用“全局画像 + 相关风格指纹 + 原文摘录”的风格上下文，不新增独立风格向量索引
- 已保存文章的历史入口收敛为 icon + tooltip，旧会话通过右侧抽屉切换；从主题新建时可先生成大纲，但必须保存为正式文档后才能继续 AI 改写和续聊
- 入模上下文改为“相关块包 + 少量最近历史 + 请求内摘要 + 事实/风格裁剪”，不再默认整篇文章全量直传；其中目标块保持完整正文，邻近上下文才允许按预算裁剪
- 全文改写始终保持块级结构与预览确认，只处理正文类块；软上限 `12`，硬上限 `20`，超过后自动分批或要求缩小范围
- 所有编辑结果先落为可恢复的批量预览，刷新后仍能恢复，当前文章内容变化后会自动转为 `stale`
- 如果编辑模型返回的不是合法 JSON，前端仍只展示“AI 返回格式异常，请重试。”，但服务端会把原始返回摘要写入日志，便于后续排查
- 主要 LLM 调用按模型上下文窗口做预算控制，接近上限时自动 compact，必要时最多重试一次
- 所有修改走 diff 预览，用户点击"应用"才落地

### 4.4 Markdown 工作区 Agent（长期形态）

- 工作区 Agent 的目标不是替代文件管理、知识库问答或画布，而是把三者连接成一个可执行的协作层。
- Agent 可以在用户指定范围内读取当前文件、目录、选中文件、检索证据、风格参考和最近对话，但不能越过用户确认的写入范围静默操作。
- 当前 Agentic Loop 工具包括：`search_knowledge`、`read_file`、`create_note`、`preview_patch_files`、`analyze_folder`、`check_links`。工具失败必须返回可读原因和下一步提示。
- 写入类工具必须通过系统层 `validateWrite` 校验；删除文件在任何路径下都不开放。
- `create_note` 新建文件按目录粒度校验授权：授权目录下可新建文件；如果任务只授权了当前 `.md` 文件，系统允许在该文件所在目录中新建文件，但不因此扩大到同目录其他文件的修改权限。
- 每个 Loop 任务开始前必须完成快照；任务完成、失败或取消后，用户可以整体回滚被修改文件和 Agent 新建文件。
- 多文件修改必须生成批量预览；文件级 patch 使用 `{ file_path, old, new }`，确认应用前再次校验文件快照和 `old` 文本。
- 新建笔记写入后会异步触发增量索引，新建文件会记录创建时 hash，回滚时如果发现外部修改会提示冲突。
- 通用知识回答必须和用户笔记依据分开表述，不能把模型自身知识伪装成来自用户工作区。
- 该能力是 Notus 的长期产品形态，当前版本已具备 Agentic Loop 多轮执行、文件级预览、任务级回滚、检索问答、风格上下文和文档级上下文；旧块级编辑能力保留为历史兼容。

### 4.5 两个创作入口

- **从现有文章进入**：编辑器工具栏"AI 创作"按钮，将当前文章解析为 Block 结构打开画布
- **从主题新建**：顶部"创作"Tab → 输入主题 → Agent 检索知识库 + 生成大纲 → 写入画布 → 保存为正式文档 → 继续逐块起草

## 5. 核心交互流程

### 5.1 首次使用

```
启动 Web 或桌面端 → /setup 引导三步(配置模型/导入笔记/完成)
→ 后台建立索引 → 文件树就绪 → 索引完成后知识库可用
```

桌面端安装包要求附带独立应用图标，并且内置的数据库与向量检索原生依赖必须按目标平台单独准备；不能直接复用普通 Node 环境下构建出的原生模块，否则会出现安装后应用无窗口、启动即失败的情况。

### 5.2 日常写作

```
打开文件树 → 选择文章 → 编辑 → 保存 → 自动增量索引（无感知）
```

### 5.3 知识库查询

```
切换到「知识库」Tab → （可选）选择当前文章或手动限定参考范围 → 输入问题
→ 先做查询理解（直接检索 / 追问 / 单次辅助改写）
→ 混合检索 + section 证据整理 + 必要时单次条件重排
→ 按回答模式生成结果（可能是追问、保守回答或正常回答） + 来源卡片
→ 可通过历史抽屉恢复旧会话或新建对话 → 点击来源卡片并在页内定位原文
```

### 5.4 AI 创作（从现有文章）

```
编辑器打开文章 → 点击「AI 创作」→ 画布模式，文章解析为块
→ AI 协作区输入指令（如 "@b2 扩写第二段，参考我的风格"）
→ 系统先做范围规划（单块 / 多块 / 全文 / 纯对话）
→ 选取相关块包 + 事实/风格上下文 → 执行器生成一组 str_replace 操作
→ 前端展示可恢复的批量预览 → 用户确认后整体应用
→ 块更新 → MD 文件同步保存 → 增量索引

复杂目标：
输入创作或写作指令 → 读取创作页“自动应用 / 手动确认”设置
→ 自动应用模式直接创建 Agent Session 和任务快照；手动确认模式先显示任务确认卡
→ Agent 多轮调用 search_knowledge/read_file/create_note/analyze_folder/check_links
→ 需要修改已有文件时生成 preview_patch_files → 自动应用或用户确认应用
→ 应用后续跑，直到任务完成、达到上限或触发异常终止 → 可整体回滚
```

### 5.5 AI 创作（从主题新建）

```

→ 大纲骨架以 SSE 逐块写入画布 → 用户调整大纲（拖拽/改标题）

→ 系统按请求范围生成单块 / 多块 / 全文预览，必要时分批执行
→ 用户确认后应用修改 → 自动索引
```

左侧文章区直接复用 WYSIWYG 编辑器和工具栏，可边看边改，也可一键收起；可见编辑区默认隐藏仅包含系统 `id` 的 frontmatter，并支持在侧边栏查看 H1-H6 大纲。工具栏除基础格式外，额外支持文本内容居中，并要求保存后继续可回显。问答区顶部展示当前文章提示、历史抽屉入口、新建对话 icon 按钮，以及“参考来源”区（自动匹配 / 手动指定文件）。历史抽屉里的每条会话提供删除图标，点击后必须二次确认；删除当前会话后回到新对话空态。顶部当前文档、文章预览头部和来源卡片在线播放统一使用可见文档标签：优先 `title`，其次显示去掉 `.md` 的文件名，最后才用占位文案，不暴露 `article_xxx`、裸 `fileId` 等技术标识。当前打开文档只影响优先检索与参考来源设置，不再切换聊天历史。左侧文章区与文件页、创作页共享同一文档的最近阅读位置，普通跨页返回时优先按文本锚点恢复；来源卡片定位和待消费来源定位优先，不会被旧浏览位置覆盖。AI 未就绪时只锁定右侧问答区，左侧文章、文件树和大纲仍可使用。命中 `clarify_needed` 时，知识库页不再返回单条文字追问，而是用底部 `ClarifyDrawer` 收集最多 `3` 个结构化条件，题目优先围绕对象、对比对象、时间范围和检索范围；答完后先进入回顾态，用户点击“开始检索”才真正续跑。InputBar：TextArea(flex:1) + 右下角固定工具组（模型选择器 + 发送/停止按钮）；模型选择器触发器固定在发送按钮左侧，窄宽度下单行省略显示，完整模型名通过标题提示与菜单项展示；生成中输入框只保留停止按钮，真正的等待态固定显示在 AI 回复气泡内，检索状态作为 loading 气泡内部的动态步骤切换；抽屉展开时输入栏禁用，收起后恢复普通提问；`v1` 不展示 `+` 附件入口。

历史抽屉里的每条会话同时提供导出按钮，导出为 Markdown 文件，包含用户/AI 消息、引用、消息 meta、Agent session、工具日志、思考文本和修改预览记录；如果会话包含 Agent Loop，历史抽屉还提供执行日志入口，可跳转到设置页日志视图并定位该会话的工具调用记录。

来源卡片点击后保持在知识库页，自动展开左侧编辑区并定位原文，可手动关闭高亮。

AI 回复头部可按回答模式显示轻量状态标记，例如“需澄清 / 证据偏弱 / 证据冲突 / 未找到证据”；生成期间聊天区本身需要显示与发送按钮同色系的简洁 loading 动画，不能只在输入框里保留“停止生成”按钮；检索状态、正文、补充说明和来源卡片保持在同一个回复容器内。

**状态：** 空态(✨ + 输入提示，不展示预制问题列表) / 索引未完成(⏳ + ProgressBar) / 模型未就绪(右侧问答区锁态 + 前往设置，左侧文章与大纲可用) / AI 回复中(StreamingText + 聊天气泡内 loading + 停止生成) / 需澄清(结构化抽屉 + 回顾确认后检索) / 抽屉收起(允许直接发新问题，同时取消旧 interaction) / 证据偏弱(保守回答) / 证据冲突(明确提示不同说法) / 检索无足够证据(文字提示) / API 错误(InlineError + 重试)。

### 6.6 AI 创作画布页（`/canvas`）

布局：Sidebar + CanvasArea(默认约 62%) + AIPanel。中间分栏可拖拽调整，并记住上次使用宽度。

**AIPanel：** 已保存文章时，顶部仅保留“查看历史对话 / 新建对话”两个 icon 按钮，旧会话通过 ConversationDrawer 抽屉展示；历史抽屉里的每条会话提供删除图标，点击后必须二次确认；删除当前会话后回到当前文章的新对话空态，不清空文章块和未保存状态。顶部当前文章标题区、对话区引用文档和来源卡片在线播放统一使用可见文档标签，不暴露内部 id 风格文案。其下是风格来源区域（自动匹配 / 手动指定） + 对话区（支持文本回复、文章分析、批量修改预览恢复，以及结构化提问抽屉恢复） + InputBar（`@b2` / `@b2-b5` / “全文”快捷项，`@` 触发当前文档块 autocomplete，支持上下键切换、回车确认、Esc 关闭，中文输入法组合态不抢键，键盘移动时列表滚动条跟随选中项；模型选择器固定在右下角发送按钮左侧，触发器单行省略，菜单项展示完整模型名；创作页专属“自动应用 / 手动确认”下拉框固定在输入框左下角，选择值持久化到浏览器本机，默认自动应用）。自动应用模式下，用户发送创作任务后直接启动 Agentic Loop，不展示任务确认卡；文件预览生成后，如果用户仍停留在当前页面和当前对话，前端自动应用并续跑。手动确认模式下，保留任务确认卡和手动预览应用流程。当系统无法稳定理解“把上面的内容写到文档中”“把刚才生成的内容写进去”这类编辑请求时，会在右侧面板底部抽屉中一次性补问最多 3 个问题；抽屉使用列表状态布局，只保留标题、状态、问题、选项、自定义输入和按钮，并覆盖原输入框，不再在消息流里内联展示卡片或重试块。最后一题不会自动续跑，而是先进入回顾态；用户点击“开始生成预览”后，前端才提交结构化答案并续跑。收起抽屉后，输入栏恢复普通提问；若此时用户直接发送新请求，旧 interaction 会被取消。高风险预览和澄清后续跑会额外显示“当前理解”摘要，并提供轻量纠偏入口；当同一条回复同时包含摘要和批量预览时，必须保留预览与应用按钮。事实参考由后台默认自动补充，并始终优先当前文档；系统入模时只选取相关块包、最近少量历史和请求内摘要，不再默认整篇文章全量直传，但目标块必须完整入模以保证 `old/new` 可应用；文章分析默认关闭，只保留后端开关；未保存的大纲草稿则显示“先保存再继续 AI 改写”的引导卡片，并禁用历史会话与输入栏。只要当前创作存在未保存改动，用户从侧边栏、顶部搜索或页内切换到其他文章前，都必须先经过统一的未保存确认弹窗；弹窗底部只提供“不保存离开 / 保存并继续”，右上角、遮罩和 Esc 可关闭并留在当前页。

创作页历史抽屉同样支持导出 Markdown，对话导出会记录消息、工具链、Agent session、思考文本和修改预览，便于复盘一次创作任务的完整执行过程。

**CanvasArea：** 创作块进入编辑态后不因 textarea 失焦自动退出；用户通过 `Mod+Enter` 或“完成”保存当前块，通过 `Esc` 或“取消编辑”放弃本次块内修改。文档内容搜索浮层只保留输入框、匹配计数、上下切换和关闭按钮，不显示额外说明文字或空查询提示。创作块区与文件页、知识库页共享同一文档的最近阅读位置；优先使用当前可见 block id 或正文文本及视口偏移恢复，找不到锚点时再回退到滚动进度。

创作页点击侧边栏文件时，不跳回文件页，而是在当前画布页读取对应文章内容并转成创作块；`?fileId=` 只作为当前画布文档的同步标记，切换中的目标文档必须等新文章真正完成加载后，才能释放路由同步保护，避免旧 query 把刚切换的新文档重新覆盖回去。
创作页如果从侧边栏新建文件后自动打开目标文档，也必须复用和普通点文件相同的切换入口，继续走未保存确认、同页路由更新和 pending 路由保护，不能直接在共享上下文里抢先切换当前文档。

**CanvasArea：** 标题 --text-3xl/700 + CanvasBlock 列表（gap:--space-1）+ AddBlockButton（dashed border）。

**CanvasBlock 六态：** 默认 / hover（border-left + 操作栏 ⠿/✏️/🗑/↻）/ 编辑中（inline textarea）/ AI 已纳入待应用预览（bg:--bg-diff-modified）/ AI 处理中（border-left 脉冲）/ 已应用（flash success 300ms）。

**无文章态：** 新建创作入口（居中 max-width:480px，主题 Input h:48px + primary "生成大纲并开始" + 最近创作列表）；模型未就绪时整体禁用并展示锁态说明。

**状态：** 加载中(Skeleton) / 模型未就绪(整页浅遮罩 + 锁态卡片) / AI 处理中(脉冲 + StreamingText + AI 气泡内柔和三点 loading) / 大纲生成中(整页蒙版 + loading 卡片，底层块内容逐步写入) / 提问待回答(右侧底部列表抽屉覆盖输入框) / 提问回顾态(确认后再继续生成预览) / 提问抽屉已失效(需要重新确认位置或重新发起) / 回答已记录但续跑失败(抽屉保留重试入口) / 高风险预览(当前理解摘要 + 轻量纠偏入口，同时保留批量预览与应用按钮)。

### 6.7 设置页（`/settings/model` 等）

**模型配置：** Embedding（Base URL + 模型名 + API Key + 多模态向量开关）+ LLM 朴素列表（配置名称 + Provider name + 模型名 + Base URL）+ [新增配置 / 编辑 / 删除]。Embedding 维度在测试后由后端记录并用于索引，不在卡片中单独展示；设置页和引导页 Step 1 使用设计稿暖色单栏卡片风格，API Key 不明文回显，也不展示“已保存密钥”类提示。LLM 新增/编辑弹窗必须提供兼容协议下拉框，支持 `OpenAI API` 与 `Anthropic`，默认 `OpenAI API`，历史配置按 `OpenAI API` 处理；LLM 保存不要求先测试连通性，列表不展示密钥状态、默认配置提示或兼容协议。知识库页和创作页以输入框模型下拉框当前选择作为全局模型选择，设置页不再提供单独的默认配置入口。LLM 预算字段仍会在后端持久化用于运行时控制，但不在列表中直接展示。

**个性化：** 独立页面只展示功能名与开关。“标题与文件名双向绑定”默认关闭；开启后，仅文件页和知识库页会在手动保存时用正文首个可见 H1 同步文件名，并在侧边栏显式重命名时反向同步首个 H1；创作页不参与这项联动。

### 6.11 布局边界

- 当前版本按桌面工作区设计，Web 与 Electron 都设置 1360 × 800 的最小宽高。
- 侧边栏折叠状态、文件树展开状态、文件树 / 大纲 tab 状态与各 tab 滚动位置会持久化。
- 文件页、知识库页文档区和创作页块区会保留页面级位置，并额外共享同一文档的最近阅读位置；普通滚动停止后再保存，切页时同步写入；显式来源定位、URL 行号和待消费引用定位优先。
- 知识库页和创作页分栏会限制左右面板下限，保证侧边文件数、文本编辑区和右侧聊天区同时可见；AI 输入框模型选择器固定在右下角并以单行省略显示。
- 侧边栏收缩态顶部仅保留展开按钮，不显示文件树 / 大纲入口。
- 已完成 AI 配置后，切往知识库页 / 创作页时通过轻量 PageTransitionOverlay 过渡，避免短暂闪出锁态；知识库页和创作页在同页切换 `fileId` 时，也保留统一的全局过渡反馈。
- 本版本不提供移动端适配，也不提供平板/手机降级布局。
- 懒猫 `.lpk` 元数据会显式声明 `ios` 与 `android` 为不支持平台，避免在移动端入口被误展示为可用应用。

## 7. 设计决策备忘

| 决策 | 选择 | 理由 |
|------|------|------|
| 侧边栏结构 | 文件树 + TOC 共用 Sidebar，Tab 切换 | 与 Typora 一致，节省空间 |
| 创作画布布局 | 左右分栏（35/65） | 类 Cursor 体验，宽屏友好 |
| 对话历史入口 | icon button + drawer 抽屉 | 降低顶部表单感，保留旧会话快速切换 |
| 上下文入模策略 | budget-aware + 自动 compact | 优先保留当前证据、相关块和最近对话，避免超限失败 |
| 风格样本策略 | 风格指纹 + 全局画像 + 自动语义匹配 / 手动覆盖 | 在效果、速度和 token 成本之间取中间值 |
| 创作事实策略 | 后台自动补充，前台只暴露风格来源 | 减少配置负担，同时保留表达控制 |
| 创作入口 | 编辑器按钮 + 独立 Tab | 覆盖"改现有"+"写新文" |
| 编辑器方案 | Tiptap + tiptap-markdown | 直接提供所见即所得与 Markdown 双向转换 |
| 配色 | Claude Terracotta + Cream | 温暖、非 AI 冷感 |
| AI 修改确认 | diff 预览 → 自动应用或用户确认 | 创作页可自动应用；手动模式仍保留确认与撤销 |
| 来源跳转 | 精确行号 + 高亮 3s 淡出 | 定位段落而非开文章 |
| AI 定位块 | Block ID + old 字段校验 | Claude Artifacts 同款 |
| 组件库策略 | Radix Primitives 行为 + 手写样式 | 比 shadcn 覆写更干净 |
