# Notus 产品设计文档（PDD）

> v3.2 · 更新时间：2026-08-13

## 2026-08-13 文件树下载与任务消息体验

- 文件树目录右键菜单在原有操作之后依次提供“上传文件”“下载目录”；“上传文件”沿用现有 Markdown 导入范围并以该目录为导入父路径。“下载目录”导出当前目录及全部子目录的 Markdown，并复用导出文件已有的图片归档能力，产物为 ZIP。文件右键菜单在原有操作之后提供“下载文件”，直接下载该 Markdown 源文件。
- Agent 任务级累计 Diff 卡主描述固定为“x 个文件修订”，次描述列出已应用、已回滚、已废弃及图片变更数量；编辑图标外框为圆形，详情按会话权限按需读取。
- 用户只上传解析附件或图片、没有输入文字或 Mention 时，系统仍为 Agent 生成内部任务并展示已上传媒体、时间和执行记录，但不展示内部默认任务文案的用户消息气泡；该显示规则在刷新历史对话后保持一致。
- 手动确认模式在生成文件或目录 Diff 时即完成 Agent 任务。用户随后应用、废弃或回滚 Diff 只更新文件和 Diff 状态，不恢复模型、Worker 或同会话队列，也不追加收尾总结。

## 1. 产品定位

Notus 是本地 Markdown 文件工作区与 AI Agent。用户在同一个工作区中管理文件、编辑正文、检索已有资料，并让 Agent 读取、创建或修改文件。

当前代码版本为 `0.1.13`；项目根目录、Web 应用与懒猫 `package.yml` 使用同一版本号，懒猫安装包命名为 `cloud.lazycat.app.notus-v<version>.lpk`。本轮只更新源码与元数据，没有重新打包 `.lpk`。

`.md` 文件是唯一真相来源。SQLite 保存索引、会话、预览和运行状态，文件被外部编辑后可重新索引。所有非删除写入都会产生可审查记录；自动确认模式保留回滚入口并继续任务，手动确认模式生成 Diff 后结束任务、等待用户独立处理 Diff。

## 2. 当前产品结构

```text
Notus
├── 顶部工作区控制：搜索、保存、编辑器开关、AI 面板开关、设置
├── 左侧 Sidebar：文件树 / 当前文件目录
└── 文件工作区（/files）
    ├── 富文本编辑器：可选展开
    └── AI 聊天面板：可选展开，可独立于文件使用
```

`/knowledge` 与 `/canvas` 保留兼容跳转到 `/files`，不再提供独立页面、导航入口或独立产品流程。

## 3. 核心体验

### 3.1 文件编辑

- 文件页保留 Tiptap 富文本编辑器与 Markdown 双向转换。
- 选中文件时可同时展开编辑器和 AI 面板；两栏之间可拖动调整宽度。
- 编辑器、AI 面板的展开状态持久化在浏览器。关闭窗口后重新打开时，恢复上次选中的文档和两者的开关组合；切换已打开文件时不重置状态。
- 用户在已运行的工作区从未打开文件状态进入某篇文件时，使用个性化设置中的默认展开值；启动恢复的已选文档不再覆盖保存的面板组合。
- 再次点击当前选中的侧边栏文件会清除当前文档选中状态，编辑器回到未选择文件的空态，AI 面板保持原状态。
- 富文本编辑器工具栏支持通过弹窗自定义行数和列数插入可编辑 Markdown 表格，首行为表头；格式、链接、引用等选中态只在正文编辑器拥有焦点且当前选区匹配时显示。
- 顶部不显示文件、知识库、创作等产品导航。顶部右侧使用搜索 icon、富文本编辑器和 AI 聊天面板两个无边框控制 icon；三个控制与设置按钮共用 32px 点击区域，搜索提示为“搜索文件”。
- 从文件树、全局搜索、Diff 或路由选中一篇文章时，若富文本编辑器处于收起状态，系统先展开编辑器再打开该文章；仅应用启动恢复的文件保留关窗前的面板组合。
- 富文本编辑器和 AI 聊天面板默认快捷键分别为 `Mod+B` 与 `Mod+U`，并可在快捷键设置中修改。
- 文件工作区会记住富文本编辑器和 AI 面板的双栏宽度；AI 输入框和消息面板共用父容器 95% 的宽度约束，在独占和双栏布局中都会随面板宽度同步变化；用户消息气泡继续右对齐并按内容保留宽度上限；消息列表在底部保留足够空间，复制和重试操作不会被输入区覆盖。
- Agent 运行、等待或排队不会锁定输入框文本编辑；但当前对话存在创建、排队或执行中的任务时，右下主按钮改为中断该对话的在途任务，而非继续提交新任务。用户可新建或切换对话后正常发送新任务，原后台任务不会因此被取消；回到原对话时，主按钮会从全部已恢复 session 重新识别。点击中断时，同一对话的 `created / queued / running` 任务一并取消，主按钮立即恢复发送，不继续把已取消 session 视为可中断任务。一次发送在服务端受理前只创建一条任务，重复点击或连续 Enter 不会新增 session；入队确认后仍可发送下一条不同任务并按 FIFO 等待。提交后先在当前界面回显用户消息并显示“任务已提交，正在准备执行”，服务端入队确认到达后以真实消息 ID 原位校正，不新增第二个气泡。每个 session 独立保留本地订阅和工具时间线；实时状态不能被尚未刷新的历史恢复状态清空。
- 工具调用和阶段性回复属于 Agent 任务记录。任务异常、SSE 断线、切换对话、刷新或关闭应用后，返回原对话仍显示已持久化的真实工具调用；已完成任务同时恢复工具记录和正式回复，已暂停任务显示继续入口与中断前草稿。用户可以先核对已完成步骤，再决定续跑或另发消息。
- 工作区不再要求浏览器或桌面窗口维持固定的 `1360 × 800` 尺寸。窄于 960px 时文件树自动收起为可展开抽屉；双栏仍可显示时，AI 面板固定为 456px，富文本编辑器压缩剩余空间；窄于 760px 且两个面板均打开时再收起编辑器与分隔线，AI 面板占满主工作区。任一面板收起后不得保留其最小宽度，剩余面板从工作区左边界占满可用宽度，内部消息列和输入框保持居中。编辑器和 AI 面板不改为上下排列。窗口重新变宽不会自动展开文件树或编辑器，必须由用户显式打开。弹窗、设置、图片预览和通知始终限制在当前视口内。
- 富文本编辑区采用独立标题输入区和正文编辑区：标题保存为 Markdown 一级标题，正文编辑器不显示 Notus 系统 Frontmatter。Agent 创建笔记时，标题输入区显示 Agent 生成的标题。
- 个性化开启“标题与文件名双向绑定”后，顶部标题输入框保存时由服务端同步一级标题和已有的 Frontmatter `title`，再以标题重命名同目录 Markdown 文件；文件树、`@` Mention 与全局搜索从刷新后的文件列表读取新名称。目标重名时正文标题仍保存，并提示未同步文件名。
- 导入 Markdown 时，文件标题默认使用导入文件名，并同步到一级标题和 Frontmatter `title`；导入不会因标题—文件名绑定而再次改名。
- AI 聊天面板的回底按钮始终位于输入区上方；图片预览覆盖层覆盖顶栏，关闭和图片名称可正常操作。
- 设置在当前工作区上方以弹窗展示，点击遮罩不关闭；标题栏不显示当前功能名称或“设置”，仅保留关闭操作，并在窄屏显示菜单 icon。各设置内容区顶部也不重复显示所属功能名，当前项由侧栏或抽屉选中态表达。模型、搜索、Skill、MCP、Agent 个性、日志、个性化、图床、存储、快捷键、关于共用 860px 最大内容列。Agent 个性页管理 `soul.md`、`style.md`、`memory.md` 的 Markdown 正文、历史与回滚；Skill 与 MCP 使用右上操作栏和紧凑列表；Skill 行显示名称、描述、启停开关，以及仅 Git 受管 Skill 可见的手动更新操作，操作栏支持 Git 安装、ZIP 导入和重新扫描。MCP 页用内容宽度、左对齐的“调用 MCP”和“MCP 服务”分隔 Notus 的外部 Server 配置与外供 Streamable HTTP、Token 管理、手动变更 Diff；个性化页使用与搜索配置相同的全宽设置区。
- 页面路由切换直接展示目标内容，不显示覆盖全屏的通用加载遮罩、Logo 或顶部转场进度条；文件树读取、保存、对话恢复与 AI 生成继续在各自操作位置提供局部反馈。
- 设置页的分段 Tab 按标签内容宽度收紧，不拉满内容列；仅当可用空间不足时在标签自身区域横向滚动，不能带动页面或设置弹窗横向溢出。
- “复制全文”复制 Markdown 源文本；本地图片路径保持 Markdown 原值，不将图片转为 Base64 写入剪贴板。
- 粘贴或插入的新图片可按图床设置保存到本地资源目录，或上传至腾讯云 COS、阿里云 OSS、Cloudflare R2。云端模式将公开 URL 写入 Markdown；上传失败时不插入图片。

### 3.2 AI Agent

- AI 面板可以在未选中文件时直接发起对话、创建笔记、整理目录或检索工作区。
- AI 面板顶栏不显示品牌标题；无消息时只展示“你今天在想些什么？”。
- Agent 任务不会把当前打开文件作为默认目标，也不会自动读取当前文件。
- Agent 正在运行、等待提问卡片回答或正在提交回答时，AI 面板保持展开。用户点击顶部开关或使用快捷键收起时，页面保留面板并说明需等待任务或回答完成。
- Agent 同时使用三份用户可编辑的全局文件：`soul.md` 每轮作为低优先级人格参考，`memory.md` 按任务相关章节提供长期偏好与决策，`style.md` 仅在创作、改写、润色、续写或翻译后的文字调整中加载。它们不能改变系统安全规则、工具权限、文件范围或危险操作确认。
- 全局文件正文保存于应用数据目录的 `agent/`，不是 SQLite 正文。用户可在设置页编辑、恢复默认、查看历史和回滚；Agent 只能读取固定文件枚举，更新长期记忆、风格或人格必须来自用户明确的长期意图。
- 同一对话中的写作目标由 Agent 结合当前指令、最近对话和工作区实时状态判断；系统不以关键词或上一轮创建记录强制指定新建或修改的文件。Agent 能定位目标时直接执行，不能定位时才主动提问。
- 同一对话中，用户继续操作刚查询、安装、启停或修改过的 Skill/MCP 时，系统以真实资源 ID 而非聊天中的名称或旧文本承接。每轮重新确认资源仍存在且状态有效；用户说“这个”“它”“改名”等而当前对象唯一时，Agent 先处理该资源，不会误把它解释成文章标题或工作区文件。最近一次资源操作存在多个同类对象时，先让用户确认对象。
- 用户反馈“图片或截图未贴入文档”时，Agent 结合当前指令、最近对话和工作区状态定位目标；目标不明时主动提问，不以近期创建笔记作服务端强制绑定。
- 服务端不会因同一对话有近期文章候选自动展示“修改候选文章 / 新建文章”卡片；提问卡仅由 Agent 在确实无法判断写作目标、范围或操作时生成。
- 用户可通过 `@` 搜索工作区文件和目录。候选主行展示文件名或目录名，次行展示一次相对路径，文件使用 `Icons.file`、目录使用 Sidebar 展开状态的 `Icons.folderOpen`，按标题、名称和路径做模糊匹配；选中后在光标处生成不可编辑的内联 mention 卡片，不在可见文本中暴露 token。
- 文件树名称在行宽不足时单行省略；只有浏览器确认名称发生实际截断时才显示文件名 Tooltip，未截断的名称不额外出现提示。
- mention 在消息数据中保存 `id / type / name / path`，并保存文字与 mention 的交错顺序；输入框和用户历史消息复用同一张紧凑卡片。目录卡片使用 Sidebar 展开状态图标。点击文件卡片可预览 Markdown，点击目录卡片可浏览目录内笔记并按需读取正文；预览隐藏 Notus 系统 frontmatter（`id / created_by / title`），正文区域可滚动。
- Mention 是可选上下文。普通文本、图片或解析附件无需引用任何文件或目录即可发送；用户可在输入框失焦后通过卡片删除按钮移除 Mention，输入框随后恢复可编辑光标并可直接发送普通任务。
- 内部 Agent 上下文使用 `@{相对路径}` 表示明确文件定位，使用 `@{folder:相对路径}` 表示目录范围。Agent 对文件在需要正文时调用 `read_file`；对目录先调用精确路径的 `analyze_folder`，再按任务读取少量文件或限定目录检索。目录引用不会默认扫描整个工作区。
- 未 Mention 文件时，Agent 根据任务决定是否使用 `analyze_folder`、`search_knowledge` 或 `read_file`。普通对话无需为了查找文件而调用工具。
- 输入支持解析附件、图片、联网搜索、模型选择、自动/手动确认、历史对话、消息复制/改写/重试、提问卡片和 diff 详情。解析附件支持 PDF、DOCX、MD/Markdown、TXT 和 CSV（CSV 按纯文本读取）；单条消息最多 10 个、单个对话最多 20 个。图片不属于附件：单条消息最多 30 张、单个对话最多 50 张。文档附件的选择器声明扩展名与 MIME 类型，但前端、上传接口和解析器均以支持的扩展名列表为最终判定；图片仍按扩展名与 MIME 类型识别，兼容 Chromium/Electron 的剪贴板文件项。图片固定走视觉上传和模型输入，不进入文档解析。附件 chip 使用内容列内的固定宽度，文件名单行省略并通过 Tooltip 查看完整名称；两类媒体按上传顺序显示在同一组 chip 中。待发送图片 chip 可打开与笔记编辑器共用的全屏预览，并在当前上传队列内切换。用户只发送图片、不输入文字时，系统以“分析图片并说明可确认内容”作为本轮默认任务。
- 模型下拉可按模型显示名、Provider 名和配置名模糊搜索。历史抽屉可按对话标题、用户消息和 AI 消息全文模糊搜索；搜索在服务端完成，不以最后一条消息预览代替完整历史。列表只显示归一化后的 120 字以内摘要，避免命中长回复时淹没其他结果。应用恢复已保存会话时，消息区先显示“正在恢复上次对话…”，完成后再显示真实消息和执行记录。仍有非终态 Agent session 的对话显示紧凑状态标记：等待回答、等待确认、可继续、正在执行或等待执行；多项任务显示数量。标记只提示状态，不承担停止或继续操作。
- 用户改写已发送消息，或在 AI 回复上点击重试时，系统都以对应用户消息为锚点删除其后的全部对话消息，并取消后续未完成 Agent session、队列任务、交互和预览。改写会保存新文本；重试保留原用户文本并复用该条消息，不新增相同用户气泡。前端只清除服务端实际取消 session 的订阅、工具记录和交互，不清除锚点之前的记录。新任务只使用截断后的服务端历史，不会把被替换的旧 prompt 或旧回复发送给模型。
- 改写提交即发起新任务并锁定编辑态；当前 textarea 同步替换为带新 prompt 的用户消息气泡。发送失败才恢复 textarea。后续消息的淡出仅为视觉动画，不延迟请求，也不使用“发送中”替换发送按钮文案。
- AI 输入区和用户消息中的图片使用纯缩略图，不显示图片文件名或大小；已发送图片与解析附件一样独立显示在用户文字气泡上方，不嵌入气泡背景。`session_created` 后实时用户消息以服务端回传的落库图片列表回填图片类型、真实消息 ID、会话归属与受控预览地址。已确认的受控地址优先于浏览器临时对象 URL，队列清理后缩略图和预览仍可用。点击输入区图片在待发送队列内预览，点击已发送消息图片则在该消息的全部图片中左右切换。
- 用户和 AI 回复都显示创建时间，精确到分钟。当天显示“HH:mm”；昨天显示“昨天 HH:mm”；前天到最近 7 个日历日内显示“周几 HH:mm”；更早显示“YYYY-MM-DD HH:mm”。时间与消息操作同一行并紧邻 icon：用户时间位于复制 icon 左侧，AI 时间位于重试 icon 右侧。纯图片用户消息在图片行下方沿用该顺序。时间不参与消息排序。
- 当前轮图片先由当前视觉模型执行一次独立识别。成功后，摘要以“图片识别结果”与 PDF、Word、Markdown、文本和网页解析结果分开保存，并自动成为同一对话的持续上下文；摘要和受控图片引用还会显式附入首个 Agent 用户消息，确保本轮直接据此回答，不会误判为没有收到图片。主 Agent 不再重复提交本轮图片 Base64，历史轮次也直接读取该摘要和受控图片引用。OpenAI Chat Completions 与 Anthropic Messages分别使用各自视觉输入协议完成首次识别；识别失败不会伪造摘要，当前轮保留原始视觉输入作为兜底。
- Agent 请求失败时，界面在对应任务的工具链中展示统一的错误信息组件，不再在消息区底部裸显示错误字符串。组件沿用 Diff 详情的暖色外壳、细边框和紧凑信息层级，展示受控的简短错误说明、错误码或可选请求编号；“继续任务”和“重试”两个操作固定在卡片右下角，不再在按钮区重复解释重试载荷，也不使用 divider 分隔。重试以错误任务对应的上一条用户消息为锚点，复用现有重试流程重新发送原 prompt、Mention、解析附件、图片和媒体顺序；不展示 Next.js、代理或其他服务端 HTML 错误页。
- 工具链只显示 Worker 已持久化的真实工具动作、模型重试、可见的“正在思考”和必须由用户处理的暂停或异常；不显示未持久化的入队、页面 loading 或 SSE 订阅。执行段仍是服务端的重试、请求窗口和批次归属边界，但工具链不显示“第 N 个执行段”或段标题；各 sub task 实际调用的工具按事件到达顺序平铺展示。“正在思考”只允许模型明确输出、面向用户的简短进度文字，并流式追加到同一工具链步骤；隐藏推理、Prompt、Provider reasoning 字段、完整工具参数、文件正文和密钥绝不进入该步骤、SSE 或历史记录。附件和网页解析步骤展示已读取的安全来源名称、来源类型、字符数、页数、重复状态、警告或错误码；网页地址不显示查询参数或片段，文件不显示上传临时路径。工具链以低干扰的单列执行记录附着在本轮回复正文之前；工具参数与结果仅在展开后按“调用参数 / 调用结果”分区显示，JSON 使用缩进格式，超长内容只在代码区内滚动。完成和运行不使用对勾或转圈；运行状态统一显示为“正在处理 N 秒”，不足一秒按 1 秒显示。`read_file` 与 `read_global_agent_file` 使用带文本行的文件读取图标，`create_note`、文件修改预览和 `update_global_agent_file` 使用文件编辑图标；名称含 `skill` 或 `mcp` 的工具优先使用各自独立的 Skill 与服务器机架图标。正在执行的任务可从记录头部停止，停止按钮不与模型选择混排。
- 工具链不再使用 Agent 头像、Agent 名称标题或独立任务卡。尚未形成最终回复时，记录紧跟该 session 的原始用户消息；形成最终回复后，记录与回复正文位于同一助手消息区域。一个对话中的每个 Agent session 都保留各自的记录，不能由后续任务覆盖。停止、继续等操作只作用于点击记录所属的 session，继续按钮在操作区最右侧。没有已确认动作或流式草稿时不显示容器。切换或新建对话只解除前端订阅，不取消后台任务；已收到和后续收到的“正在思考”内容均先持久化，回到原对话、刷新或重新打开应用时从 session timeline 恢复并续接。已暂停任务直接展示恢复说明与“继续任务”，用户显式停止的任务保持停止，不提供恢复入口。任务有最终助手消息时，唯一的累计 Diff 卡位于该消息气泡及消息操作区之后，而不插入工具链与回复正文之间；尚无最终消息时才附在对应用户消息的执行记录下方。Diff 详情在 960px 以下隐藏固定侧栏，通过标题栏“文件”入口以悬浮抽屉查看文件列表，正文和长行只在详情内部滚动，不撑开页面。可恢复错误的错误卡片只保留自身边界，不再叠加工具链容器的上下边框；早期日志仅显示隐私保护后的工具摘要；修改预览、提问卡片和可恢复错误显示“需要处理”，不伪装成已完成。累计 Diff 的每个文件或目录详情显示所属执行段和批次，不显示文件正文以外的额外请求上下文。
- 消息操作与任务展示状态分离：用户消息和 AI 回复的复制始终可用；用户消息改写与 AI 回复重试不会因其他 Agent 正在运行、中断或恢复而禁用，只保留模型不可用、消息不具备操作条件和自身提交中的必要限制。
- AI 独占工作区将输入与消息限制在 860px 最大内容列，固定 456px AI 面板和更窄窗口保持单列。输入默认三行；常规宽度下确认方式显示“自动 / 手动”，其 Tooltip 与无障碍名称保持完整操作语义。输入工具栏按面板宽度分三档：680px 以下将确认方式收缩为带 Tooltip 和无障碍名称的 icon Tab，560px 以下再将联网和 MCP 缩为 icon，390px 以下将附件与联网/MCP 保持在首行，确认方式以紧凑 icon Tab 独占下一行，模型选择与发送按钮与其底线对齐并固定在右下角。模型名、联网和 MCP 都通过不越出视口的 Tooltip 保留完整含义，联网显示“联网搜索”，MCP 根据可用状态显示“MCP 工具”或“暂无 MCP 服务”。390px 以下继续隐藏次要图片添加入口；“滚动到最新消息”位于输入停靠区的右上方，不覆盖工具链正文。顶部“已保存”在紧凑图标态保持透明静止背景；只有未保存入口在 hover 或按下时给予错误色反馈。控件收敛使用短促过渡，并遵循减少动态效果系统偏好；全程不发生遮挡、控件挤压或页面级横向溢出。
- 未发送的 AI 输入草稿长期保存在当前浏览器的 IndexedDB 中，包含文本、Mention 及其顺序、待发送图片和解析附件；刷新页面或重新进入工作区后恢复，不设置过期时间。服务端创建 Agent session 并持久化用户消息后，立即回传 `session_created` 供前端回显 prompt、图片和受控预览地址，再执行附件解析和图片识别；收到该确认后输入文本、图片、附件和草稿同步清理。在此之前上传或建会失败则保留草稿。
- 文件工作区同时保存当前打开的有效 Agent 对话 ID。应用重新打开时，先读取历史列表；该会话仍存在才恢复消息、待处理预览和交互状态，记录失效、读取失败、新建或删除当前会话时清除该 ID。用户主动新建对话后，即使旧会话的恢复请求尚未返回，也不得把旧消息、待处理卡片或会话 ID 写回新对话。
- 用户要求把当前或历史对话图片整理进笔记时，`@` 文件、明确路径、当前输入或最近对话能唯一确定目标才直接生成预览。当前编辑器打开的文件不构成隐式目标。
- 目标不唯一时，Agent 检索后以提问卡片给出最多 3 个候选，并提供“手填已有路径”和“新建笔记”；只有选中后两项才填写 Markdown 相对路径。已确定笔记但未指定位置时，Agent 写入语义匹配的小节；没有匹配时在文末新增“调研图片与整理”。
- 提问卡片的前后题导航使用无文字箭头 icon；单选答案会自动进入下一题，文本输入时保留方向键的原生编辑行为。未提交的回答保存在当前文件工作区内存中，收起编辑器、切换文件或改变面板组合不会要求用户重答；页面刷新后以服务端 pending interaction 恢复卡片。回答全部可见问题后，卡片在同一组件内列出全部问题与答案，用户可逐项修改并直接提交续跑；提交后由原 session 的后台任务从保存点继续，不能因权限票据类型不匹配而中断。已回答提问不是消息尾部的独立卡片，而是所属 Agent session 工具链中的“已回答问题”步骤：默认折叠，紧跟“等待回答”步骤；展开后显示问题、回答与本地化时间，图标使用对话气泡，不显示代码图标。同一个用户任务只会生成一张待回答提问卡片，不会因 API 模块重复初始化而重复询问。Worker 与 SSE 订阅端共享进程级事件源，提问卡片、工具链和最终回复在任务执行时即时显示；断线或刷新仍从持久化事件恢复。
- 显式粘贴 URL 会自动直连读取，不依赖联网搜索开关。GitHub 根仓库链接优先读取仓库 README，并区分仓库不存在、README 缺失、限流和抓取失败。读取成功后，后续搜索为空只能表示没有补充结果；最终回答和消息卡片以服务端来源状态为准，不会把成功读取的链接说成未找到。
- Agent 的知识库与联网检索分别使用每任务最多 5 个查询：首轮固定执行原词在首位的 3 个改写查询，证据不足才补 2 个。重复调用和换词会复用任务缓存。完成消息的脱敏“已使用资料 / 文件变更”卡片由代码开关控制，当前暂时关闭；不展示原始 Prompt、网页全文、Cookie 或密钥。关闭卡片不影响检索、缓存、内部回执和 `get_task_activity`。
- Agent 任务受理后，消息下方立即显示工具链头部与已等待/处理中计时；运行态统一显示“正在处理 N 秒”，不足 1 秒按 1 秒显示，不使用“处理 1 秒不到”或“0 秒”。每条服务端真实工具事件和可见“正在思考”内容按到达顺序进入时间线，并通过轻量入场动画维持可读节奏。任务结束时默认折叠工具链，等待确认、提问或恢复操作时保持展开；排队、内部循环和推测性 loading 不伪装为工具调用。
- 工具链“已处理”代表整个 Agent 任务的执行时长：历史记录优先使用任务队列的开始和结束时间，实时记录从受理到终态事件计时；工具步骤只说明过程，不能缩短或替代总时长。

### 3.3 写入与工具边界

- 工具集：`search_knowledge`、`read_file`、`create_note`、`preview_file_revision`、`preview_patch_files`、`preview_file_operations`、`ask_question_card`、`analyze_folder`、`check_links`、只读的 `get_task_activity`，以及用户开启联网搜索后可用的 `web_search`。
- Agent 可以创建、修改、重命名和移动 Markdown 文件或目录；删除文件和目录不开放。
- 单文件大范围修改优先走 `preview_file_revision`，由代码生成 diff 并校验 hash。
- 小范围或多文件正文修改使用 `preview_patch_files`；文件和目录操作使用 `preview_file_operations`。
- 对话图片在预览阶段以 `notus-conversation-image` 受控引用保留在 Markdown 草稿中。应用预览前先校验文件未 stale，再按图床设置复制到本地资源目录或 COS、OSS、R2，最后写入相对路径或公开 URL。
- 图片新增、移除、替换随 operation set 保存。DiffDialog 在文本 diff 上方直接显示新增图、移除图，或并排显示替换前后的图片；每条关联操作集的 Agent 回复都保留“查看详情”入口，重新打开历史对话后仍可查看创建、修改、重命名和移动的 Diff。侧边栏的 Markdown 文件名和正文顶部完整路径均可打开文档，打开时先关闭弹窗并展开编辑器。回滚只恢复 Markdown，不删除本地资源或对象存储对象。

### 3.4 Skill 与 MCP

- 桌面端会发现本机与 Notus 管理目录中的有效 Skill。输入 `@` 时，文件、目录和 Skill 使用同一候选菜单；明确选择的 Skill 只绑定到本次 Agent session，不自动读取其正文。
- Agent 可以根据用户明确选择或当前任务，从受控目录调用 `load_skill`，再按 Skill 的明确引用调用 `read_skill_file`。Skill 文本仅作为任务参考，不能改变 Agent 的安全、数据访问或确认规则。
- Agent 也可代办资源安装：用户给出无凭据 HTTPS Git 地址后直接安装 Skill；给出名称、传输方式和连接参数后直接新增并测试 MCP，不额外显示确认卡片。Skill 同名不覆盖，MCP 名称不重复。Streamable HTTP 默认使用 HTTPS；只有用户明确要求且当前会话来自直接本机访问时，才能为 `localhost`、`127.0.0.1` 或 `::1` 开启本机 HTTP；生产 Web 还需部署者显式设置 `NOTUS_ALLOW_LOOPBACK_HTTP_MCP=true`，且不得在反向代理部署中开启。Header 作为密钥保存，不能出现在列表、工具回执或日志中。stdio MCP 仅桌面端可添加。
- MCP 输入入口位于 Agent 输入框右侧，是与联网一致的任务级自动开关：只有当前运行环境可见且已启用的 Server 存在时才能点击开启并弹出只含“自动”的下拉项，再次点击关闭。每次新任务会携带这项 `off / auto` 选择，由服务端决定动态 MCP 工具集合。控件不显示指定 Server、传输方式或说明文案；没有可用 Server 时按钮保持禁用、菜单关闭，异步可用性检查完成后将旧 `auto` 偏好归一为关闭，Tooltip 显示“暂无 MCP 服务”。菜单在输入工具栏上方展开时不受窄面板工具区裁剪，确保“自动”选项可见。设置变更、Agent 完成 MCP 新增/修改/启停/删除和窗口重新聚焦都会即时重查可用数量；是否已有工具缓存不影响前端可开启性。
- Git 安装 Skill 只输入 HTTPS 仓库地址。系统依次尝试 `main`、`master`，仓库根目录必须有有效 `SKILL.md`；安装目录和 Skill 标识采用 Frontmatter 的 `name`，不要求与仓库名一致。设置页会按需比对当前 Git 源的 `SKILL.md` 内容哈希，只有远端版本确实不同才显示“更新”。更新使用原仓库重新拉取 `main` / `master`，要求 `name` 不变，并在 staging 校验成功后原子替换；完成后重新检查并隐藏无差异的更新入口。失败保留旧版本，不做后台检查或自动更新。clone 根目录缺少或安装期间失效时，界面显示受控的安装源错误，不展示临时目录的底层文件系统异常。
- ZIP 安装通过设置页的拖放或文件选择入口提交单个 `.zip` 压缩包，最大 100 MiB。压缩包可包含多个 Skill；服务端在隔离临时目录中校验路径、链接、文件数量与解压大小，只有发现有效 `SKILL.md` 后才写入受管目录。导入默认拒绝同名目录；用户显式开启覆盖后才替换同名受管 Skill。成功后刷新 Skill 列表，失败不留下半成品。
- 设置页或 Agent 完成 Skill 启停、重新扫描、安装、Git 更新或卸载后，当前已打开的文件工作区立即重新读取有效候选；无需刷新页面即可用 `@` 搜索新启用的 Skill。
- Notus 在 Electron、Web 和懒猫运行环境均扫描其可用的 Skill 根目录。懒猫只扫描 Notus 受管目录；每次扫描使用单一批次标记，当前批次已发现的 Skill 不会被标为缺失。stdio MCP 与本机外部 Skill 扫描仅在 Electron 桌面端可用；Web 与懒猫只使用其管理目录和 Streamable HTTP MCP。
- MCP Server 配置与工具缓存持久化在应用数据库中，不通过文件扫描决定是否显示。工具缓存超过 5 分钟后，Agent 在选择已启用 Server 前自动尝试刷新；刷新失败不阻断任务，可继续使用上次成功缓存。
- Notus 可同时作为外部 Agent 的 MCP Server。外部调用只支持 Streamable HTTP，以 Bearer Token 鉴权，并固定使用 `/api/mcp`；Token、Server 与待确认变更的设置管理接口使用受保护的 `/api/settings/mcp/*`。懒猫只将外供入口声明为 `public_path`，不会放行管理接口。一个 Token 固定自动应用或手动确认模式，并独立配置工具开关。默认开启文件名/路径搜索、文件列表、读取笔记、Skill 列表和 MCP Server 摘要；创建、局部修改、完整替换、移动、重命名默认关闭。`get_change_status` 只为手动确认 Token 显示和授权，自动 Token 不注册该工具。删除和联网搜索永不对外开放。手动写入会在 MCP 设置页的待确认变更区显示 Diff，应用时再次校验文件哈希和局部 `old` 内容。创建或轮换后的一次性 Token 明文输入框尾部提供复制 icon，不另设复制按钮行。
- Agent 新增 MCP 时，Header 和 stdio 环境变量按密钥保存，Agent 工具状态、SSE 摘要、回执和运行日志不回显其原文；用户主动输入的原始聊天消息按当前会话留存策略保留。
- 设置导航中的 Skill 使用参考图所示的两层等高等距立方体线性图标，不使用单独的底部高亮，并和其他导航项一样继承默认文字色；当前项选中时才随父项使用强调色。MCP 使用标准横向双层服务器机架图标，快捷键使用键盘图标，模型配置使用机器人图标；同类入口保持一致。
- 窄屏设置弹窗使用暖色外壳、清晰边界和独立的内容背景，外壳与内部内容不再都呈现为白色；外壳背景覆盖 Dialog body，内容层单独使用主背景，避免四周出现白色过渡；设置导航抽屉、内容区和遮罩保持明确层级，窄屏下不产生横向溢出。
- 会话图片临时文件保存在 `<sessionDir>/images`，通过消息元数据与会话逻辑绑定。当前策略不因 Agent 完成、取消、过期、回滚或笔记应用而自动销毁；删除会话记录也不会物理删除临时文件。上传失败产生的中间文件会清理，已写入笔记的永久资源独立保留。
- `@b1` 等画布块引用和 `preview_canvas_blocks` 不属于当前产品能力。

## 4. 主要用户流程

### 4.1 直接与 AI 协作

1. 用户打开 `/files`，无需选择文件。
2. 在右侧 Agent 输入任务。
3. Agent 只在任务需要时读取、检索或分析目录。
4. 需要写入时生成预览，按确认模式应用，并刷新文件树与当前编辑器。

### 4.2 编辑文件并与 AI 协作

1. 用户从文件树选择 Markdown 文件。
2. 系统按个性化默认值展开编辑器和 AI 面板；同一轮后续文件切换保留当前面板状态。
3. 用户编辑正文，保存后触发增量索引。
4. 用户在 AI 面板输入任务，可用 `@` 引用任意工作区文件或目录，也可上传图片和解析附件。
5. 若当前编辑器有未保存内容，发送 Agent 任务前先保存，避免 Agent 读取旧文件版本。
6. 输入中的文本、文件 Mention、图片和解析附件会持续保存在浏览器草稿中；服务端创建 session 并接收用户消息后立即清理，上传或建会失败时保留，浏览器刷新不会丢失未完成任务。

### 4.3 文件与目录 Mention

1. 用户输入 `@` 或部分文件名。
2. 输入框按文件名、目录名、标题和路径过滤工作区节点。
3. 候选项主行显示名称、次行显示路径，支持上下键、回车和 Esc。
4. 文件或目录选中后在当前位置插入结构化 mention 节点，并以可删除、可预览的紧凑内联卡片展示。
5. Agent 内部接收等价 token；对文件按需要调用 `read_file`，对目录先调用精确路径的 `analyze_folder`，再在目录范围内选择少量文件读取或检索。
6. 文件树可拖至 AI 输入框，在落点插入同一结构化 Mention；输入框和历史消息中的文件/目录卡片均有可点击悬停样式。文件预览会在悬停时预取正文，打开时保持稳定内容区；弹窗标题是可点击的文章名，点击后打开富文本编辑器，完整相对路径显示在弹窗左下角。Skill Mention 悬停仅展示描述 tooltip，不打开文章预览。

### 4.4 对话图片整理进笔记

1. 用户在调研或问答时上传图片，并要求整理进某篇笔记。
2. Agent 使用当前轮图片，或从历史图片清单中按需读取少量图片；不会把整段会话图片重新送入模型。明确要求贴入图片而草稿遗漏受控引用时，服务端会补齐当前会话缺失引用。
3. 目标明确时，Agent 读取目标笔记并生成完整修订或新建笔记预览。目标不明确时，卡片收集笔记选择和条件路径。
4. DiffDialog 展示文字与图片变更。新增图片直接显示缩略图，不重复显示“新增”标签；替换图片保留原图、新图和方向提示，移除图片保留移除标识。手动确认和自动确认都在应用时执行图片落盘，并沿用用户当前选择的本地、COS、OSS 或 R2 存储方式；任一步失败或文件已变化时，笔记正文保持不变。
5. 图片识别前后的 Agent 工具链明确显示“查看图片”动作，并直接展示本轮已读取的受控图片缩略图；同一图片只计一次，缩略图按原图比例展示、不显示文件名，点击复用全局图片预览。实时、补发和刷新恢复均复用同一记录；含图片的完成态记录保持可见，不显示已经解决的旧模型错误。这只说明运行意图和对象，不改变图片入库、预览或写入笔记的权限边界。

## 6. 个性化与持久化

- 个性化设置提供“默认展开富文本编辑器”“默认展开 AI 聊天面板”和图片上传位置。图片上传位置以本地、腾讯云 COS、阿里云 OSS、Cloudflare R2 的分段 tab 展示；窄屏自动缩写为“本地 / 腾讯 COS / 阿里 OSS / R2”，悬浮紧凑标签时 Tooltip 显示完整名称且不换行，并保留完整无障碍名称；未配置的云图床仍可点击，会提示并提供前往配置的链接，但保持当前已选位置不变。
- 设置弹窗在 700px 以下不再把完整设置导航铺在顶部；标题栏提供“打开设置菜单”入口，导航从左侧抽屉进入。选择设置项或点击抽屉外的遮罩均关闭抽屉，外层设置弹窗仍仅能通过关闭按钮或 Esc 退出。
- 图床设置页通过与搜索配置一致的服务商 Tab 分别编辑阿里云 OSS、腾讯云 COS、Cloudflare R2 的 Bucket、地域、Endpoint、对象前缀、公开访问基础 URL 与密钥。首次进入时展示个性化页当前选择的云服务；本地存储时回退到首项阿里云 OSS。保存参数不改变图片上传位置，密钥不会在设置页面回显。
- 所有设置页的分段 Tab 始终限制在所属内容区内；空间不足时仅 Tab 自身横向滚动，不带动设置页或弹窗横向溢出。
- 默认值只在已运行的工作区从无文件状态打开文件时生效。
- 顶部开关、当前文件、当前 Agent 对话和分栏宽度保存在本地浏览器；关闭窗口后重新打开时恢复为关闭前的工作区组合。当前对话仅保存 ID，不保存或改变服务端会话内容。
- AI 输入区的未发送草稿保存在 IndexedDB，不设置过期时间；图片和附件以 Blob 保存，恢复时重新创建浏览器 `File` 对象和预览 URL。该草稿不写入服务端会话，也不跨浏览器同步。
- 侧边栏、文件树展开状态、文件树滚动位置和当前文件仍按原有工作区状态保存。

## 7. 验收标准

1. 用户不选择文件也能发送 Agent 任务。
2. 选中文件后，富文本编辑器与 AI 面板可并排显示并调整宽度。
3. 顶部没有知识库和创作导航，两个面板开关可用且持久化。
4. `@` 可按文件名、目录名和路径匹配，候选显示一次名称和路径；Agent 能精确读取 Mention 文件，或先分析 Mention 目录。
5. Agent 未收到 Mention 时不会将已打开文件作为隐式上下文。
6. 再次点击当前选中侧边栏文件会清除选中状态并移除 `fileId` 路由参数。
7. 工具栏弹窗可自定义表格行数和列数，插入后生成可编辑表格并能写回 Markdown。
8. 复制全文的纯文本内容是 Markdown 源文本，图片不会转成 Base64。
9. 本地和三家对象存储模式均可插入图片；对象存储模式的 Markdown 使用公开 URL，上传失败时不产生图片节点。
10. Agent 能把当前或历史对话图片写入明确笔记，并只在应用时复制图片到用户配置的存储位置。
11. 目标不唯一时，提问卡片能选择候选笔记、手填已有路径或新建笔记；单选自动推进，全部回答在同一张卡片中复核。
12. DiffDialog 能显示图片新增、移除和替换；回滚不会物理删除图片资源。
13. 刷新文件工作区后，AI 输入文本、Mention 顺序、待发送图片和解析附件仍可继续编辑；发送成功后浏览器草稿被清理。
14. 在 1366、1024、768 和 390px 宽度下，工作区、设置和通用弹窗不由 Shell 产生页面级横向溢出；宽表格、代码块和 diff 仅在自身内容区横向滚动。
15. 关闭并重新打开应用后，仍存在的当前 Agent 对话自动恢复；Skill、MCP 和快捷键入口使用各自的语义图标，Skill/MCP 设置页不显示顶部说明段落。
16. 图片或截图贴入任务即使模型草稿遗漏引用，Diff 仍显示图片变更；本地和三家对象存储模式均按当前设置持久化，云端失败不写入笔记。
17. Agent 可受控管理 Skill 与 MCP：Skill 安装、覆盖和卸载、MCP 删除均需在复用提问卡片样式的资源确认卡确认，等待时不新增 AI 消息；查看 MCP 与日志不会显示密钥值。
18. 主 LLM 的临时错误按服务端执行段独立计数；不同执行段的重试在工具链中分别显示，同一执行段内只更新一条记录。
19. 一个 Agent session 只显示一张“本任务累计修改”卡。任务完成、失败、中断或存在待处理 Diff 时，只要存在文件或目录净变化，该卡都可打开；已有最终助手消息时卡片固定在该消息气泡和操作区之后。
20. 自动确认按批次应用后继续原任务；手动确认生成 Diff 即完成原 session，用户应用或废弃当前批次不会恢复模型或队列任务。

## 2026-08-01 Agent 失败恢复与全局 Agent 设置收口

- 主 LLM 遇到临时网络、限流或 5xx 错误时最多额外重试 5 次。额度、Key、权限或模型可用性需要用户处理时不盲目重试。仍未恢复时，任务与 checkpoint 保留，错误作为工具链步骤显示，用户在原任务上继续，不生成最终助手错误消息。
- 可恢复错误进入等待态后，服务端先释放旧 run lease；前端收到 `run_error` 后立即解除 loading 并开放“继续任务”和消息改写，SSE 心跳仍可继续存在。用户立即点击或快速重复点击只恢复一次原任务；仍在执行的真实 run 继续受并发保护，界面不直接展示内部冲突码。用户从输入框发送新的 prompt 时，会结束同一会话仍在等待用户处理的提问、预算确认或模型恢复任务，让新任务立即进入 FIFO 队首；原错误卡的“继续任务/重试”仍优先恢复原 checkpoint。改写或重试前也会结束旧的非终态队列任务。
- Agent 个性设置页以与图床一致的 540px 可响应定宽 Tab 切换 `soul.md / style.md / memory.md`。页内说明和文件用途文字已移除，编辑面只保留文件状态、Markdown 内容、历史、恢复默认、取消和保存。
# Agent 后台任务连续性（2026-08-01）

Agent 任务属于会话的持久化工作，不属于浏览器连接。发送后立即显示队列位置；切换对话、刷新页面、关闭页签或关闭 Electron 窗口不会停止它。窗口关闭时应用收至托盘，显式退出后下次启动自动恢复未完成任务。模型临时错误暂停后，用户仍可继续输入新任务；同一对话按发送顺序执行。提问卡和回答作为对话时间线的一部分保存，历史回答默认折叠。
