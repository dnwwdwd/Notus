# 文件工作区 Agent 全流程业务文档

> 更新时间：2026-08-02
> 适用范围：`/files`、`FileAgentWorkspace`、Agent Loop、文件 Mention 和预览应用。

## 1. 入口

用户进入 `/files` 后，右侧 AI 面板可独立使用。选择文件只影响左侧编辑器和 TOC，不为 Agent 自动增加当前文件上下文。

顶部可通过 `Mod+B` 展开或收起富文本编辑器、通过 `Mod+U` 展开或收起 AI 面板；用户可在快捷键设置中调整这两个组合键。

关闭窗口后重新打开时，工作区恢复上次选中的文件、编辑器和 AI 面板开关、分栏宽度。启动恢复的文件保留这一组合；用户从文件树、全局搜索、Diff 或路由打开任意文件时，富文本编辑器都会先展开，AI 面板开关和分栏宽度保持不变。再次点击当前文件会取消选中，编辑器回到空态，AI 面板和分栏状态保持不变；如果当前内容未保存，先经过离开保护。

布局会随可用宽度调整，但不改变上述状态与数据流：960px 以下文件树自动收起为临时抽屉；双栏仍可显示时 AI 面板固定 456px，编辑器消化剩余宽度；760px 以下且持久化的编辑器、AI 面板开关同时为展开状态时，当前渲染收起编辑器，AI 面板占满工作区。窗口重新变宽不反向展开文件树或编辑器，用户显式操作后才恢复；窄屏不把编辑器和 AI 面板改为上下排列。

文件工作区初始化时读取本地保存的编辑器宽度和 AI 面板宽度；拖动分栏并释放后更新两项宽度。AI 输入区默认保持 3 行文字高度，输入与消息共享 `min(860px, calc(100% - 32px))` 内容列；消息列表底部预留输入区高度，回底按钮固定在输入区上方，消息操作不会被覆盖。560px 以下工具栏收敛为单列，次要控制可横向滚动，模型选择和发送操作分开对齐。

Agent 输入区的未发送草稿写入浏览器 IndexedDB，长期保留文本、Mention 结构与待发送图片/解析附件 Blob。页面刷新或重新进入工作区时恢复草稿；该记录不提前创建服务端会话媒体，也没有自动过期时间。

## 2. 发送任务

1. 用户在 Agent 输入框输入文本，可上传解析附件、图片或开启联网搜索。图片支持 PNG、JPG、JPEG、WEBP、GIF；粘贴时同时识别文件扩展名和 MIME 类型，并在 `clipboardData.files` 为空时读取 `DataTransfer.items`。通用附件入口选中的图片也会自动分流到图片上传接口，图片与附件的 chip 按选择顺序混排。用户只发送图片时，前端生成“分析图片并说明可确认内容”的默认任务。点击待发送图片 chip 会打开与笔记编辑器共用的预览层，只在当前图片队列中左右切换；移除该图片或清空队列会关闭预览。
2. 解析附件与图片分别计数：单条消息最多 10 个附件、30 张图片；单个对话最多 20 个附件、50 张图片。图片不计入附件。
3. 如果富文本编辑器内容未保存，文件页先保存 Markdown。
4. 前端创建 `goal: 用户任务：<输入>`，不传 `active_file_id`，不添加当前文件、路径或块快照。
5. 前端同时提交 `attachments`、`images` 和按选择顺序保留的 `media_items`。模型下拉可按模型和 Provider 模糊过滤；MCP 仅提交 `{ mode: 'auto' }` 或 `{ mode: 'off' }`，自动模式由服务端按已启用 Server 选择工具。`/api/agent/loop/start` 合并去重后持久化用户消息、Agent session 与队列任务，返回 `202`、真实消息 ID、受控图片地址和队列位置；前端随即回显 prompt 与入队步骤并连接会话事件 SSE。历史会话尚未刷新为空时，恢复逻辑不得清空这份实时回显。后台 Worker 才解析本轮非图片附件、执行图片识别和 Agent Loop。切换会话只关闭 SSE，不取消 Worker；同一会话后续消息按 FIFO 入队。
6. 用户消息落库和回显后，服务端以当前视觉模型识别本轮图片：OpenAI Chat Completions 用 `image_url` data URL；Anthropic Messages 用 `image/source/base64`。成功结果作为独立的“图片识别结果”来源文本保存，并带回 `notus-conversation-image` 受控引用；当前轮把摘要和引用显式放入首个 Agent 用户消息，后续历史轮次自动读取持久化文本，两者都不重复发送原图。
7. 识别失败或模型未返回文字时不保存空结果，也不伪造识别结论；当前轮保留原始视觉输入作为兜底。历史图片不再提供 `list_conversation_images`、`read_conversation_images` 工具，也不自动重新注入 Base64。
8. 会话图片使用 `notus-conversation-image://<message-id>/<image-id>` 受控引用。引用和预览接口均校验图片属于当前会话，服务端不接受客户端传入的临时文件路径。
9. `AgentWorkspace` 在执行期间显示工具步骤、流式输出和预览；工具步骤只来自已确认入队、Worker 或持久化运行事件，不能由页面 loading 伪造“准备上下文”等状态。任务时间线保持独立节点；有真实步骤或流式草稿时，顶部显示 N 头像与“Notus Agent”名称，没有活动时不渲染身份块或容器。时间线行显示状态图标、动作名和单行摘要，参数/结果按需展开；停止入口只显示在运行任务的时间线头部，输入模型区不显示停止图标。恢复历史对话时，`created / queued_resume` 自动重连后台任务，`waiting_retry / waiting_model_recovery` 直接展开“继续任务”，`cancelled` 不可复活。最终回复下方的“已使用资料 / 文件变更”卡由代码开关控制，当前暂时关闭，不展示原始工具调用、完整网页正文、Cookie、密钥或 Prompt。服务端在用户消息入库并创建 session 后立即推送 `session_created`，同时回传已经校验归属的图片清单、真实消息 ID、受控引用和预览 URL；前端以这份数据立即构造实时用户消息，并优先使用受控 URL，不能在队列清理后继续请求已回收的浏览器对象 URL。确认用户消息已入库后，前端立即清空输入文本、图片、附件和浏览器草稿；SSE 或 LLM 后续失败不会恢复已经接收的媒体。
10. 上传或创建 session 失败时，保留媒体队列并恢复本轮发送前的文本与 Mention，避免任务草稿丢失；用户移除单个 Mention、图片或附件后保存最新状态。
11. `/api/agent/loop/start` 返回非 JSON 失败响应时，前端只呈现受控错误提示、HTTP 状态和可选请求编号，绝不将响应 HTML 作为聊天内容展示。SSE 初始化前的运行时异常由服务端写日志并返回含请求编号的 JSON；可据此定位实际 500 根因。
11. Mention 是可选的文件或目录上下文。普通文本、图片或解析附件均可单独发送。删除 mention 后，输入区立即恢复可编辑光标，后续文字继续参与发送和草稿保存。
12. 用户改写一条已发送消息时，`session_created` 回传的真实用户消息 ID 用作截断锚点。服务端先保存改写内容、删除锚点之后的全部消息，并取消后续未完成 session、交互和预览；提交时前端立即以新 prompt 替换 textarea 为用户消息气泡，并启动新任务，失败时才恢复编辑态。后续气泡的淡出动画不阻塞请求，按钮仍显示“发送”。新任务只读取截断后的数据库历史，不能读取被替换的旧 prompt。连续 SSE 的 `session_created`、交互和结束事件先同步更新前端 session ref，提问卡片回答始终携带当前 token。
13. 待发送图片和已发送消息图片均用纯缩略图展示，不显示文件名或大小。已发送图片与解析附件一样独立显示在用户文字气泡上方，不嵌入气泡。`session_created` 后的实时消息由服务端确认的 `images` 回填图片类型、会话 ID 与预览 URL，不依赖临时对象或混合媒体列表内的标记；点击待发送图片时只预览当前输入队列，点击已发送消息图片时预览组件装载该消息的全部图片，可左右切换、按 Esc 或点击遮罩关闭。解析附件仍显示文件 chip。
14. 消息入库的 `created_at` 会映射为前端消息创建时间；实时用户消息由 `session_created` 携带同一时刻，实时 AI 回复在完成时记录。前端把 SQLite 的 UTC 时间转换为本地时间并隐藏秒。当天显示“HH:mm”；昨天显示“昨天 HH:mm”；前天到最近 7 个日历日内显示“周几 HH:mm”；更早显示“YYYY-MM-DD HH:mm”；时间进入消息操作行并紧邻操作 icon：用户时间在复制左侧，AI 时间在重试右侧；纯图片用户消息在图片行下方显示时间。

## 3. Mention 文件和目录

1. 用户输入 `@` 或部分名称。
2. 前端从 `allFiles` 和文件树搜索文件名、目录名、标题和路径。候选主行显示名称，次行显示一次相对路径。
3. 选择候选后在当前光标位置插入不可编辑的内联 `MentionItem`；普通文本不写入 `@{...}`。卡片可整体删除，点击直接打开预览。
4. 新消息在 `meta.mentions` 保存 `id / type / name / path`，在 `meta.mention_segments` 保存文字与 mention 的交错顺序。发送给 Agent 的内部 `goal` 按该顺序携带等价 token，System Prompt 因而继续把文件视为明确引用，并在需要正文时调用 `read_file`。
5. 目录 mention 的内部 token 为 `@{folder:path/to/folder}`。Agent 先调用 `analyze_folder({ folder_path: "path/to/folder" })`，再按任务挑选少量文件读取或以该路径作为 `search_knowledge.scope_paths`。
6. 编辑器顶部标题保存会提交标题和正文；开启标题—文件名绑定时，服务端先同步可见一级标题及已有 Frontmatter 标题，再重命名文件。文件页刷新文件树后，Mention 候选立即使用新文件名、标题和路径；全局搜索同样从该刷新结果读取。导入仍以文件名生成标题，不触发改名。
6. 若目录结果截断，Agent 继续按子目录分批分析；目录 Mention 不触发根目录扫描或全库检索。
7. 用户消息和历史消息共用 `MentionItem`。旧记录中的 token 在读取时转换为卡片，不回写数据库。点击文件按需读取 Markdown，并隐藏 Notus 系统 frontmatter 后在可滚动正文区展示；点击目录先列出目录内笔记，选中后才读取正文。
8. 若没有 Mention，Agent 只在任务确实需要定位文件或资料时使用 `analyze_folder`、`search_knowledge` 或 `read_file`。

### 3.1 Skill Mention

1. 前端在同一个 `@` 候选菜单显示启用且有效的本机 Skill，使用书册星标图标。设置页或 Agent 完成启停、重新扫描、安装、Git 更新、卸载后，工作区立即重新拉取候选，无需刷新页面。
2. 选中后消息保存 `type: 'skill'` 的结构化 Mention，内部 goal 使用 `@{skill:<id>}`；该 token 不会被当作工作区文件读取。
3. 服务端把 Skill ID 写入 session。Prompt 要求 Agent 先调用 `load_skill`，再按需调用 `read_skill_file`；未明确选择时，Agent 只能依据目录摘要主动决定是否加载。
4. 用户要求安装 Skill 时，Agent 收集无凭据 HTTPS Git URL 后单独调用 `install_skill_from_git`；安装沿用 Git 分支回退、校验与受管目录事务，同名不覆盖。直接工具成功或资源确认卡确认完成后，当前工作区立即重新读取 Skill 候选。

## 4. Agent 工具和预览

- `search_knowledge`：召回语义材料和事实。
- `read_file`：读取完整 Markdown 文件。
- `analyze_folder`：读取实时目录结构，处理新建、移动、重命名目录时优先使用。
- `create_note`、`preview_file_revision`、`preview_patch_files`、`preview_file_operations`：创建可审查写入结果。
- `ask_question_card`：任务明确但缺少结构化信息时暂停并等待用户回答。
- `web_search`：用户开启联网搜索且服务商可用时注册。
- `search_knowledge` 与 `web_search`：模型仍传单个 query，服务端以原词为首项执行 3 个去重查询；全部缺少充分证据时再补 2 个。每个 task、每个来源最多 5 项，重复或换词调用复用缓存。查询回执保存阶段、状态、结果数、耗时、摘要和脱敏错误码。
- `get_task_activity`：只读当前 session 的查询、来源和工具记录，供 Agent 如实回答“第一轮用了什么关键词”“是否读到 README”“什么未执行”。
- `load_skill`、`read_skill_file`：只面向有效且启用的 Skill，受根目录与大小限制保护。
- `add_mcp_server`：用户提供名称、传输和连接参数后直接保存并测试。Streamable HTTP 默认要求 HTTPS；本机 HTTP 只接受 `localhost`、`127.0.0.1` 或 `::1`，并要求当前 session 由服务端判定为直接本机访问。stdio 仅 Electron 桌面端注册。Header/env 以密钥保存，结果与回执只返回脱敏配置状态；测试失败保留 Server，供用户随后在设置页修正。
- 受 MCP 选择与权限约束的动态 MCP 工具：工具名使用 Server ID 哈希别名，避免和内置工具冲突；参数校验按工具声明支持默认 JSON Schema 和 Draft 2020-12，仍拒绝不符合 Schema 的输入。

### 4.1 MCP 选择与授权

1. 用户点击输入框右侧 MCP 图标，在当前运行环境至少有一个可见且已启用 Server 时开启或关闭自动模式；选择随本地输入偏好保存，并作为本次发送参数传给 Loop。选择只保存 `off / auto / server`；服务端把本机 HTTP 权限独立写入 session。只有直接回环 socket、精确回环 Host 且没有代理转发头的请求可获得权限；生产 Web 还需部署者显式设置 `NOTUS_ALLOW_LOOPBACK_HTTP_MCP=true`，且只能用于未经过反向代理暴露的本机部署。Agent 新增、修改、启停或确认删除 MCP 后会立即重新读取可用 Server。无可用 Server 时按钮禁用，旧自动偏好归一为关闭；悬停按钮显示“暂无 MCP 服务”。
2. 自动模式根据任务与已缓存工具的名称、描述选择少量相关 Server。未匹配或连接失败的 Server 不阻塞内置 Agent 工具。
3. MCP 不再有逐工具授权。当前任务打开 MCP 后，Agent 可调用自动选择出的已启用 Server 工具。
4. 选择后恢复同一个 session；工具缓存超过 5 分钟时，服务端会先尝试刷新已选 Server 的工具列表；刷新失败不阻断任务并继续使用上次成功缓存。

### 4.2 全局 Agent 文件

1. 运行时通过统一文件服务在应用数据目录初始化 `soul.md`、`style.md`、`memory.md`，只补建缺失项。正文与历史快照不进入笔记索引或 SQLite 正文。
2. 新任务按安全规则、Notus 指令、人格、相关记忆、任务材料、写作风格、Skill/MCP、用户请求组织 Prompt。人格每轮加载；记忆按章节和任务词挑选；只有写作任务加载风格。
3. 设置页、Agent Loop 与 Agent 工具都调用同一服务。保存、恢复默认、回滚和 Electron 外部编辑均创建可追溯快照；写入使用预期 Hash，冲突不会静默覆盖。
4. Agent 读取只限三种固定文件。用户明确“记住”时可更新记忆；未明确时只能建议。风格或人格只有用户表达长期修改意图后才能更新。

### 4.3 对外 MCP Server

1. 外部 Agent 通过 `/api/mcp` 使用 Streamable HTTP，并用 `Authorization: Bearer <token>` 识别一个 MCP Token；Token、Server 与变更管理 API 独立位于受保护的 `/api/settings/mcp/*`。
2. Token 在 MCP 设置页创建、编辑、停用、删除或重新生成。原始 Token 只在创建或重新生成时显示一次；后端只保存哈希。
3. Token 的工具开关决定外部 `tools/list` 内容。默认只读工具支持按文件名/相对路径搜索、列文件、读笔记、列 Skill、列 MCP Server 摘要；外部没有删除或联网搜索能力。
4. 所有写入要求最新 `expected_hash`，局部修改还要求 `old` 精确唯一命中。自动 Token 通过校验后直接写入；手动 Token 生成 `change_id` 并等待 MCP 设置页确认，只有手动 Token 可授权并调用 `get_change_status` 查询。
5. 手动变更应用前重新校验文件；文件已变化时标记 `conflict` 并不覆盖。拒绝后状态为 `rejected`。Token、Header、环境变量和文件正文都不进入外部审计摘要。

同一对话的写作任务不把界面当前文件、最近创建文件或 operation set 当作隐式目标。Agent 根据当前指令和最近对话判断是否承接已有文件；需要定位时自行读取实时工作区，再按既有预览工具执行。“图片或截图没有贴入文档”遵循同一判断规则。

Skill/MCP 的跨轮承接走独立的资源上下文，不能依赖上述文件目标或最近聊天文本猜测。每次新建 Agent session 会从同一对话的 `agent_run_logs` 与已完成 `resource_approval` 中提取最近的资源 ID，再调用 Skill/MCP 领域服务重新读取当前状态；失效或已删除对象不注入。Prompt 把这段结构化资源上下文放在最近对话文本之前：用户说“这个”“它”“改名”等且当前对象唯一时，Agent 先按该 ID 查询或管理资源，不能跳去文章、文件或工作区；同一次最近资源操作出现多个同类对象时必须先澄清。

删除文件和目录始终不开放。`preview_canvas_blocks` 不在工具定义中。

## 5. 确认、刷新和历史

自动确认会应用通过安全检查的写入；手动确认通过 DiffDialog 逐项应用、废弃或回滚。Diff 顶部完整路径和侧边栏的 Markdown 文件名都可打开文档：先关闭弹窗、展开编辑器，再选择目标文件。打开路径时先从当前消息同步最新 operation set；本地快照未命中时刷新文件树后再报不存在。图片引用在预览中保持临时状态；明确贴入、插入或整理对话图片的任务若草稿漏掉受控引用，服务端在创建预览前补齐当前会话的缺失引用。应用前先检查文件是否 stale，再通过和编辑器共用的图片存储服务写入本地资源目录或 COS、OSS、R2，随后把最终地址写入 Markdown。上传失败或临时图片失效时，正文不会写入，也不会回退到本地。Agent 可能修改文件后，前端刷新文件树；若当前编辑器文件受影响，清除缓存并重新载入。

历史抽屉支持切换、删除、导出和日志入口。文件工作区将当前有效对话 ID 保存在浏览器端；应用重新打开后，历史列表中仍存在该 ID 时自动恢复其消息、待处理预览和交互，失效 ID 静默清除。为兼容历史记录，文件工作区的 Agent 会话继续按 `kind=canvas` 读取和保存；用户界面不显示品牌标题，空态使用“你今天在想些什么？”。

会话图片临时文件保存在 `<sessionDir>/images`，通过用户消息元数据保存会话归属。当前实现不会在 Agent 完成、取消、过期、回滚或删除会话时自动销毁这些文件；因此历史图片仍可按受控引用读取。上传失败的中间文件会清理，应用到笔记后的本地资源或对象存储对象单独保留。

## 6. 提问卡片

Agent 调用 `ask_question_card` 后，右侧底部显示 `ClarifyDrawer`，覆盖输入区域。未提交回答保存在文件工作区内存；收起编辑器、切换文件或改变双栏组合不会清空答案，刷新页面后从会话详情中的 pending interaction 恢复卡片。服务端为回答、续跑、取消和回滚分别签发短期 scoped ticket，票据只放在请求头或请求体。回答与唯一 `resume_job` 在同一事务内创建；前端再通过 `resume_job_id + resume_ticket` 获取 run lease 并续跑，重复提交只返回同一 job。运行、等待回答或提交回答时，AI 面板保持展开。前端以运行序号隔离旧 SSE；服务端通过状态机、乐观锁和 lease 保证同一 session 同时只有一个 run。答题阶段的前后题使用箭头 icon，焦点不在文本输入框内时可用左右方向键切题，前进仍要求当前题已回答。单选完成后自动显示下一道可见题；全部回答后，同一组件切换为逐题复核列表，用户可回到任一题修改后直接提交。

服务端不因近期文章候选自动创建写作目标卡片。当前指令和最近对话由 Agent 判断；目标、范围或操作无法定位时，Agent 才调用同一张提问卡片收集必要信息。

图片整理的目标笔记无法唯一确定时，卡片最多显示 3 个候选笔记，并提供“手填已有路径”“新建笔记”。候选直接保存 Markdown 相对路径；只有手填或新建被选中时，条件题才要求填写路径。目标确定但没有位置时，Agent 写入语义匹配小节；没有匹配时在文末补“调研图片与整理”。

## 7. 图片 diff 与回滚

DiffDialog 在文本 diff 上方显示“图片变更”。新增只显示新图；移除显示原图和移除标识；替换并排显示原图、新图和方向提示。预览中的会话图片通过受控预览接口显示；已写入笔记的本地图片通过既有内容图片代理显示，对象存储图片使用公开 URL。回滚只恢复原 Markdown，不会物理删除本地资源或对象存储对象。

## 8. 编辑器图片上传

图片粘贴和工具栏选图不进入 Agent Loop。它们直接请求图片上传 API，并通过 Agent 图片写入共用的图床存储服务写入本地资源目录或对象存储。对象存储成功后，编辑器插入公开 URL；失败时保持当前编辑内容并提示错误，不产生 Markdown 图片引用。

图片预览层挂载到页面根节点，覆盖顶部菜单栏；关闭、计数、图片名称和左右切换按钮始终可操作。

## 9. 编辑器表格插入

工具栏“插入表格”打开弹窗，用户输入行数和列数后创建带表头的可编辑表格。表格节点沿用现有 Markdown 双向转换链路，保存后写回 GFM 表格语法。

## 10. Agent 资源管理

Agent 通过 `list/get/create/validate/install/update/set/uninstall Skill` 和 MCP 管理工具处理资源。安装、覆盖、卸载和删除会创建 `resource_approval` interaction，前端复用提问卡片样式并保持 session 为等待状态；确认后的服务端结果作为原 Tool 回执恢复同一 session，不追加空助手消息。取消不产生半成品，Skill 草稿保留一天。Skill 内容只写 Notus 受管目录，禁止写入笔记工作区。用于跨轮承接的日志摘要只保留资源 ID、名称、启停、传输和确认结果等脱敏定位信息；不记录 Header、env、Token 或 Skill 正文。

## 11. 模型请求失败与继续任务

1. 进入模型请求前，Loop 保存包含当前任务、已完成工具回执和待执行上下文的 checkpoint。
2. timeout、网络、临时限流和可恢复 5xx 最多额外重试 3 次，工具链显示重试次数。余额、Key、权限和模型问题立即等待用户处理。
3. 失败后不追加助手错误消息。工具链展开脱敏错误和继续按钮，session 保持 `waiting_retry` 或 `waiting_model_recovery`。
4. 用户重试原模型、切换模型，或修复额度/密钥后点击继续。新 run 取得 lease 并从原 checkpoint 恢复，不重复执行已有成功回执的工具。
5. 服务端在把继续入口发送到前端前释放已停止 Loop 的旧 lease；等待态允许接管仍处于 API 收尾窗口的旧 run。前端保持按钮禁用到 SSE 结束，并同步拦截快速重复点击。session 仍为 `running` 时继续保护真实并发执行。

### 断线、切换对话与应用重启

1. 用户切换历史对话、新建对话、删除当前对话或离开工作区时，前端递增 run sequence 并断开本地 SSE，清空当前页面的 loading、session、stream、error 和工具步骤；这只是 UI 解绑，不发送任务取消请求。
2. 服务端感知 SSE 断线后将未完成任务保留为 `queued_resume`。用户返回原对话时，可恢复卡和 scoped ticket 从会话详情重新加载。
3. 若 Electron 或服务进程被直接关闭，旧进程可能来不及执行 lease 释放。新进程读取会话时检查 `active_run_id`：lease 已过期或当前控制面没有对应活动 run，就以乐观锁改为 `queued_resume`，保留 checkpoint。
4. `queued_resume / waiting_retry / waiting_model_recovery` 表示任务已经停住，不禁用输入框；工具链继续按钮仍恢复原 session。只有真实运行中的请求和待回答 interaction 会锁定输入。
5. `progress / artifact / final` 在发送 SSE 前写入 session timeline。返回原对话时，前端按时间线重建模型重试、工具开始/完成、错误和中断前回复；旧任务没有 timeline 时读取 run logs 作为兼容。回复草稿只用于说明中断前进度，不写成 final 消息。
5. 刷新或重开应用后，会话详情为上述等待状态重新签发短期恢复票据，前端重建同一工具链错误卡。
